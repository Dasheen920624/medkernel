## 目标
把通知中心页**真实化**：聚合各源通知（待办/异常/同步/安全），去重、低打扰、已读回执，**不前端造通知**。

## 现状（搬迁时核查 2026-05-30，以 `frontend/src` 为准）
页面**已存在待真实化**：`pages/clinical/Notifications.tsx`（路由 `/notifications` 已注册 `app/router.tsx`；另有 `/notifications/settings` 设置页）。本卡＝去占位/mock + 接 [SVC-CLINICAL-03](SVC-CLINICAL-03.md) 通知 API + 六态/五维 RBAC 齐全。

- 已实现：`Notifications.tsx` 删除旧“通知接口尚未接入”占位，改为消费 `useWorkflowNotifications` / `useReadWorkflowNotification`，展示真实通知、级别、已读状态、患者 / 就诊上下文、来源跳转、单条已读和当前页全部已读。

- 未冒领：通知免打扰时段设置仍在 `/notifications/settings` 后续收口；待办派生通知、外发投递、同步事件通知需要后续 PR 按真实来源接入，不得伪造投递成功。

## PR2 实施边界（2026-06-04，PR #371 已合并）

- 已覆盖：免打扰启用、时段、CRITICAL/HIGH 绕过、站内 / 邮件 / 短信 / 移动推送通道偏好均回写后端；PR2 阶段页面明确外部通道仅保存个人偏好，真实投递需后续接入。
- 未冒领：待办派生通知、同步事件通知和真实外发投递仍需后续 PR；安全 / 危急通知不得被免打扰静默。

### PR12 免打扰感知与安全绕过提示（2026-06-05，本地验证）
- 已实现：通知中心读取真实通知设置 API，展示个人免打扰是否生效、时间窗口与绕过级别，并在通知行上区分“免打扰中”和“安全绕过”。
- 已覆盖：CRITICAL / HIGH 通知在免打扰生效时仍展示为安全绕过，不被页面静默；INFO / LOW / MEDIUM 等非绕过级别只做低打扰标识，不在浏览器本地过滤，避免破坏服务端分页；设置接口失败时给出“免打扰状态暂不可确认”提示，通知列表仍保持可读。
- 未冒领：本 PR 仍不展示外部投递回执，不声明短信 / 邮件 / 移动推送 / Webhook / 院内消息真实送达；外部通道继续只走 `NOT_CONNECTED` 补偿登记。

### PR13 来源跳转安全降级（2026-06-05，本地验证）
- 已实现：通知中心的“打开来源”仅在后端 deepLink 为站内应用路径时渲染；外部 URL、协议相对 URL、`javascript:` 与包含空白 / 控制字符或反斜杠的 deepLink 均降级为“来源暂不可跳转”。

- 未冒领：本 PR 不验证来源系统真实可达性，不展示外部投递回执，不新增真实发送连接器。
