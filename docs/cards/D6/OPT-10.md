## 目标
定义并落地**插件和生态安全边界**：第三方插件**只读优先、受控写入需门禁**（权限 + 审计 + 数据主权 + 临床安全），插件**不得绕引擎直写权威数据、不得作权威源**，越界即拒。

## 现状（2026-06-07）
已建立租户隔离的插件登记、能力声明、授权与禁用状态机；能力只能绑定`ServiceContractCatalog`，写能力必须填写审批理由，临床写能力必须确认临床安全。本期不暴露通用插件执行或数据库直写入口。

## 功能要求（原子可测条目）
- [x] FR-1 能力声明：插件声明所需能力（读/写/调用），按最小权限授予。
- [x] FR-2 只读优先：默认只读；写入须显式门禁（权限 + 审批）。
- [x] FR-3 受控写入：能力只能绑定引擎服务契约（[SYS-02](../D0/SYS-02.md)），无直写权威库入口。
- [x] FR-4 临床安全门禁：临床写能力必须显式完成安全确认。
- [x] FR-5 数据主权 + 审计：插件按租户隔离，登记、授权和禁用全审计；越界拒绝。

## 接口契约 / 页面契约

## 视角清单（11 视角逐条）
1. 产品架构：生态扩展的"安全闸门"。
2. 产品体验：N·A（技术契约；管理在 [DEVCON-01](DEVCON-01.md)）。

4. 临床医疗安全：★触临床插件过红线/分级门禁、不绕引擎。
5. 知识与数据治理：插件不可作权威源、不污染权威数据。
6. 安全合规与监管：★权限 + 审计 + 数据主权；越界拒绝留痕。
7. 集团化与多租户治理：插件授权按租户隔离。
8. 集成与互操作：★只经引擎契约（[SYS-02](../D0/SYS-02.md)），受控集成。
9. 运维 / SRE / 国产化：插件可禁用/熔断。
10. 质量与真实性审计：★只读优先、受控写入有据、不绕引擎、不作权威。
11. AI / 模型治理与可降级：AI 类插件受同等边界约束。
