## 目标
生产可长期稳定引用的医疗数据元与上下文字段基础发行版，为接口、规则、路径、评估和知识资产提供唯一语义定义。

## 功能要求（原子可测条目）
- [ ] FR-1：每个数据元具有稳定 canonical ID、中文名称、定义、数据类型、长度/精度、基数、允许空值语义和官方来源版本。
- [ ] FR-2：数据元显式绑定单位、值集、编码体系、隐私分级、适用资源/场景和有效期。
- [ ] FR-3：选定官方数据元/数据集发行版须全量导入，文件数、条目数和 SHA-256 与发行清单一致，禁 Top-N。
- [ ] FR-4：上下文字段目录与数据元一一引用；同义展示名不得生成新 canonical ID。
- [ ] FR-5：模型只能辅助解析和差异解释，禁止生成官方数据元 ID、定义、类型或值域。

## 接口契约 / 页面契约
- 复用 `FIELD_CATALOG`、知识来源/版本、包发布和服务端分页接口；不新增同构资产表。
- 导入请求携带 sourceVersion、manifestHash、licenseRef、expectedFileCount、expectedItemCount 和幂等键。
- 缺来源、清单不一致、重复 ID、非法类型/基数或引用缺失时失败关闭并返回 traceId。

## 数据与迁移
- 内容复用 `mk_context_field_catalog`、`mk_version_asset_version`、来源/版本/引用表；如现有字段不足，在实施阶段以五方言迁移补 manifest/compatibility 元数据。
- canonical ID + namespace + source version 唯一；tenant/org/version/audit 字段齐全。

## 视角清单
1. 产品架构：所有运行资产先引用数据元，不各自定义字段语义。
2. 产品体验：普通用户看中文名称，专家模式看 canonical ID、版本和来源。
3. 系统与数据架构：支持十万级字段分页、批量导入、幂等重跑和 P95 门禁。
4. 临床医疗安全：剂量、单位、检验值等关键数据元缺定义时禁止生成高风险资产。
5. 知识与数据治理：官方清单全量对账，发布后不可原地改。
6. 安全合规与监管：每项带隐私分级、许可和适用边界。
7. 集团化与多租户治理：平台主源只读，机构仅做映射/覆盖，不改 canonical 定义。
8. 集成与互操作：绑定标准资源字段和版本，映射方向可追溯。
9. 运维 / SRE / 国产化交付：支持离线包、断点续传、校验报告和回滚。
10. 质量与真实性审计：条目数/hash/引用完整性证据可复算。
11. AI / 模型治理与可降级：B0 确定性导入；模型关闭不影响使用。
