## 5. 权限根因

当前授权链：

```text
默认角色权限
+ 租户 role_permission ALLOW/DENY
+ 前端 requiredRoles
+ 前端 requiredPermissions
+ 服务层直接角色判断
```

主要问题：

- 同一规则维护四次；
- 菜单可见不等于服务可执行；
- 旧角色成为状态机隐形前置；
- 租户覆盖可制造难以解释的权限组合；
- 角色数量与现实人员完全不匹配。

正确收口：

```text
固定职责权限 + 组织/数据范围
```

权限原子和数据隔离保留；租户覆盖、前端角色门和服务角色判断删除。

## 6. MFA 核查

当前事实：

- 密码成功后立即签发完整 JWT；
- 登录请求没有 TOTP 字段；
- `mfaRequired` 只决定是否跳转绑定页；
- 高风险守卫只检查数据库中是否已绑定，不检查本次会话是否验证过 TOTP。

结论：当前实现是“绑定门槛”，不是真实 MFA。

上线决策：

- `medkernel.auth.mfa.required=false`；
- 开启后登录必须验证 TOTP；
- 未绑定账号只获得绑定用受限会话；
- 高风险守卫检查当前会话 `mfa_verified`；
- 不再按角色维护 MFA 名单。
