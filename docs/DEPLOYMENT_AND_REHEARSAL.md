# 部署与完整上线演练

## 1. 验收目标

本文是全新项目从单一 V1 数据库基线部署到正式可用验收的唯一演练入口。134 环境必须验证
[完整产品范围](PRODUCT_SCOPE.md)，不能用少量规则、单个知识分类、页面巡检或接口存活代替
整套系统验收。

上线结论必须同时覆盖：

1. 六层产品能力；
2. 13 类标准患者资源；
3. 13 类版本化医疗资产；
4. 11 个知识内容分类；
5. 完整医疗语义族与专病十阶段；
6. 全医疗专业领域的代表性权威资产；
7. S0–S40 业务场景和七类业务服务组合；
8. 平台标准版本、两家差异化机构和机构生效版本；
9. 人工维护、权威来源解析和全中枢大模型候选生成；
10. 管理与生产工作区、引擎核心、嵌入、API/事件、离线交付五种形态；
11. 全集团组织层级及全部第三方系统族；
12. 无模型、断连、缺数、冲突、撤回、回滚、重启和备份恢复。

演练只接受本次候选在 134 真实产生的自动化结果和必要的脱敏人工证据。历史截图、旧环境记录、
伪造模型结果和本地模拟结果不能作为上线证据。

## 2. 候选门禁

部署前必须全部满足：

1. 后端、前端、CLI、MCP、数据库生成器、部署脚本和浏览器 E2E 全量通过；
2. T-GATE、配置边界、迁移约定、中文注释、Shell 断言语义和 `git diff --check` 通过；
3. `node scripts/db/generate-migrations.mjs --check` 证明五方言 V1 来自同一模式源；
4. 资产目录契约证明 13 类资产都有身份、版本、正文、校验、依赖、发布、运行和回滚闭环；
5. 字段目录契约证明所有非派生字段落到 13 类标准患者资源，派生字段有确定性求值器；
6. 四职责覆盖全部菜单和运行端点，内置超级管理员仅用于首次接管和应急；
7. MFA 默认关闭；开启后的真实 TOTP 登录另行通过；
8. 临床入口不接收离线交付文件、领域、资产版本或机构生效版本选择参数，由服务端锁定当前机构生效版本；
9. 模型服务不可用时系统返回真实降级状态，B0 主链仍可运行；
10. 浏览器 E2E 验收机已安装中文 CJK 字体（OpenCloudOS 可用 `google-noto-cjk-fonts`），截图证据中文可读；
11. 公网外部模型的患者上下文外调必须由前台或授权接口配置数据最小化策略；`NONE` 只表示保留非核心业务值，
    后端仍强制遮蔽姓名、证件、手机号、地址、患者编号、身份证后四位等核心标识；
12. 候选交付文件、数据库模式摘要和前后端资源都绑定同一完整 40 位本地提交哈希。

表数量、迁移版本和资产目录数量必须从候选构建清单读取，不在文档或脚本外重复维护常量。

## 3. 134 备份、恢复预演与清库

先执行目标环境预检：

```bash
sudo bash deploy/onprem/medkernel-fresh-deploy.sh --validate-environment-only
```

浏览器 E2E 和发布后验收会使用截图证据证明真实页面状态；验收机必须具备中文字体。OpenCloudOS/RHEL
系环境推荐预先安装：

```bash
sudo dnf install -y google-noto-cjk-fonts
fc-cache -f
fc-match 'Noto Sans CJK SC:lang=zh-cn'
```

若显式 CJK 字体匹配和 `fc-list :lang=zh family` 都没有返回 Noto CJK、思源、文泉驿或同等级 CJK
字体，截图会出现方块字，不能作为中文产品体验证据。

清库前固定执行：

```text
核对目标主机与部署根目录
→ 备份数据库、交付文件、外置配置和运行目录
→ 在隔离数据库恢复备份
→ 对恢复库执行结构、关键数据和可启动性校验
→ 保存脱敏恢复证据
→ 停止现有服务
→ 清空目标数据库和本次允许重建的运行目录
```

确认恢复预演通过后，从当前候选执行 V1 部署：

```bash
sudo bash deploy/onprem/medkernel-fresh-deploy.sh \
  --jar /path/to/medkernel.jar \
  --frontend /path/to/dist.tar.gz \
  --service-unit /path/to/medkernel.service \
  --deploy-script /path/to/medkernel-deploy.sh \
  --nginx-conf /path/to/medkernel.nginx.conf \
  --source <40位本地提交哈希> \
  --expected-host <134目标机hostname> \
  --external-base-url https://<正式域名或已信任SAN地址>/medkernel \
  --expected-flyway-version <候选迁移版本> \
  --expected-business-tables <候选模式清单表数> \
  --confirm-fresh \
  --confirm-database medkernel
```

脚本必须完成：

```text
安装唯一候选
→ 从空库执行 V1
→ 对照候选模式清单核验表、约束、索引和中文注释
→ readiness 与首次接管
→ 外部 HTTPS、可信证书和严格 TLS
→ 输出脱敏部署证据
```

清库后禁止把旧程序重新连接到新数据库。脚本不得输出数据库口令、JWT 密钥、字段加密密钥、
模型凭据、首次接管令牌或恢复码。

TLS 验收要求严格证书链、SAN、有效期和浏览器/脚本可信访问；不把 ACME 作为唯一实现方式。内网、
专有云或 134 这类固定地址部署可使用已纳入信任的本地 CA/SAN 证书，并通过 `MEDKERNEL_TLS_CA_FILE`
显式校验；绑定正式公网域名时应使用公网可信证书。任何 `--insecure` 或跳过证书校验的结果都不能作为
上线证据。

## 4. 完整演练数据集

演练数据必须是合成且医学上自洽的数据，不得使用真实患者明文。数据集至少包含：

- 两家机构、不同组织树、四职责账号和不同机构扩展；
- 集团、医院、院区/成员机构、科室、病区、团队、专科中心/MDT 和共享中心；
- HIS、EMR、LIS、PACS、病理、护理、药房、医保和随访等代表性来源系统；
- 13 类标准患者资源的正常、缺失、冲突、重复、乱序和撤回样本；
- 诊断、药品、检验、检查、手术、耗材、医嘱、科室、文书和随访项院内码；
- 11 个知识内容分类的公开权威来源和引用锚点；
- 覆盖内外妇儿、急诊、重症、药事、护理、医技、肿瘤、慢病、院感、公卫、质控、医保等
  专业领域的代表资产；
- 覆盖疾病诊断、症状体征、检查检验、药品、手术技术、器械耗材、指南证据、公式量表、护理、
  路径连续照护、病历医保、公卫感控、综合照护、中医药、制度质量和来源有效性语义族；
- 至少一条完整覆盖筛查分诊、诊断鉴别、风险、治疗、执行候选、监测、出院、康复随访、结局和
  持续改进的专病路径；
- 13 类版本化资产的 V1、代表性 V2、机构同源覆盖、机构新增和停用墓碑；
- 正常、高风险、证据不足、依赖断裂、模型不可用和外部系统断连用例。

知识与结构资产生成必须引用允许使用的权威来源。公网部署的系统本身可以处理患者信息；当调用公网
API 模型、外部模型服务或 Codex/CLI 生成知识时，也可以在授权用途内使用患者上下文，但发送前必须
完成最小必要、核心敏感字段屏蔽、目的绑定、责任确认、租户/机构边界和审计，证据和日志不得含患者
明文。院内本地模型可在授权范围内使用必要敏感信息，仍须保存敏感边界、用途、调用摘要和留存策略。
大模型输出必须保存提供方、模型版本、提示版本、输入摘要、输出摘要、引用、时延、校验结果和 AI 标识，
不得伪造，也不得直接形成临床事实、机构生效版本或自动医嘱。

真实前台演练必须至少覆盖一条患者资源写入和一条患者上下文模型使用边界写入：患者主索引只能提交脱敏姓名、
性别、年龄、身份证后四位等必要字段；模型使用边界必须从页面确认公网模型可使用患者上下文的前提、
字段允许范围、脱敏算子、敏感级别和责任确认阈值。脚本可校验结果，但不得绕过页面生成这些证据。

## 5. 十段全系统演练

准备可信 HTTPS 地址、运行目录、首次接管令牌文件、外置凭据文件和本机模型提供方后运行：

```bash
export MEDKERNEL_RUNTIME_ROOT=/zoesoft/medkernel/var
export LAUNCH_WEB_BASE_URL=https://<正式域名>/medkernel
export LAUNCH_API_BASE_URL=https://<正式域名>/medkernel/api/v1
export LAUNCH_BOOTSTRAP_TOKEN_FILE=/zoesoft/medkernel/conf/bootstrap-init-token.txt
export LAUNCH_CREDENTIALS_FILE=/zoesoft/medkernel/var/credentials/current-launch.json
export LAUNCH_MODEL_PROVIDER_CODE=ollama-launch
export LAUNCH_MODEL_PROVIDER_TYPE=OLLAMA
export LAUNCH_MODEL_PROVIDER_ENDPOINT=http://127.0.0.1:11434
export LAUNCH_MODEL_VERSION=medkernel-qwen25:1.5b-v1
export FULL_KNOWLEDGE_MANIFEST_PATH="$PWD/scripts/knowledge/manifests/full-knowledge-rehearsal-1.0.0.json"
export LAUNCH_SOURCE=<RC0 的 40 位 candidateCommit>
export LAUNCH_RUN_ID=<同一 RC0 的 run-id>

node scripts/release/full-system-rehearsal.mjs
```

编排器按以下顺序执行，任何阶段失败都不得生成整套通过结论。最后的完整产品范围覆盖审计会重新读取
前置阶段证据；任一前置阶段失败、覆盖矩阵缺项、`SKIPPED` 或 `UNKNOWN` 都不能生成 `PASSED`
总索引。审计同时按 `docs/contracts/release/launch-ledger.v1.schema.json` 生成恰好
`LAUNCH-01` 至 `LAUNCH-15` 的机器总账；每项绑定同一 `candidateCommit`、`runId`、判定时间、
要求范围、实际证据范围和逐条前置证据引用，自由文本“已通过”不能替代 `PASSED` 机器状态。
审计随后由 `summarizeLaunchLedger` 反算 `launch.ledger.zero-unknown`：15 项必须全部通过，
`FAILED`、`UNKNOWN`、`SKIPPED`、缺证、未解释失败、人工豁免、未分类缺口和四类开放缺口必须
全部为零；任一非零只输出 `FAILED`。归零摘要与总账绑定同一候选、运行标识和判定时间，并原样进入
十阶段总索引；删除摘要、篡改计数、漂移 run-id 或仅把顶层状态改成 `PASSED` 均不能放行。
总控会在进入最终覆盖审计前生成 `source-provenance.json`：仅允许九个固定前置阶段路径，逐文件记录
同一 RC0 的候选提交、运行标识、捕获时间和 JSON 内容 SHA-256。审计会重新读取并计算摘要；旧
run-id、最终审计自证、白名单外路径、判定后的时间或摘要漂移都会直接阻断。

### 5.1 基础治理

- 完成首次接管、两家机构、组织、任职、账号和四职责创建；
- 验证菜单、端点、组织范围、审计、MFA 关闭态和按需开启态；
- 验证超级管理员不可作为日常职责分配。

### 5.2 数据与互操作

- 登记代表性院内系统并验证签名、时效、重放、幂等、重试和死信；
- 导入院内主数据，建立院内术语到标准术语的不可变映射；
- 落地 13 类标准患者资源，验证单位归一、字段目录、数据质量和原始证据摘要；
- 形成临床事件和上下文快照，由服务端锁定当前机构生效版本。

### 5.3 全知识与全资产生产

- 11 个知识内容分类逐类完成来源登记、解析、引用、候选、校验、发布、代表性换版和撤回；
- 完整医疗语义族逐项证明有结构化落点，不以 11 个内容标签代替医学对象模型；
- 全医疗专业领域至少各完成一组可运行的代表性权威资产；
- 13 类版本化资产逐类完成人工维护或生成、自动版本、正文校验、精确依赖和测试向量；
- 模型矩阵逐项覆盖来源、解析、术语、规则、路径、诊断、护理、报告、评价、随访、运营测试和
  自然语言访问；模型只生成草稿/解释，不手工指定版本、不直接发布；
- 验证项目说明书与患者报告解读分别维护和运行。

### 5.4 平台、机构与生效版本

- 发布不可变平台标准版本；
- 两家机构分别建立同源覆盖、新增资产和院内字典映射；
- 分别按领域、场景、路径、单项资产和任意混合集合进行部分上线；
- 自动补齐运行必需依赖，拒绝缺失依赖、危险版本和空壳资产；
- 为每家医院创建不同的不可变机构生效版本并切换当前版本；
- 验证平台升级差异、机构冲突、停用墓碑、回滚和历史重放；
- 导出、校验并导入平台标准版本文件、同机构备份文件和跨机构草稿文件。

### 5.5 临床与治理运行

- 诊断支持：推荐诊断、鉴别诊断、依据和下一步建议；
- 检查检验：项目说明、检查/检验候选、重复提示和患者报告解读；
- 用药与治疗：过敏、禁忌、相互作用、剂量、监测、治疗和医嘱候选；
- 路径：候选入径、医师确认、固定路径版本、规则分支、推进、变异、退出和随访接续；
- 专病全周期：十阶段逐项运行或记录明确不适用原因；
- 急危重、护理、康复、院感、公卫、MDT、围术期、重症、特殊人群、肿瘤、慢病和药事；
- 病历、医保、病案和评价：问题证据、整改、复核、指标和评级材料；
- 推荐卡、任务、通知、反馈、医师确认和禁止自动开嘱。

这些运行用例必须覆盖 S0–S40；允许按公共引擎分组执行，但不得漏掉任何场景。

### 5.6 交付接口与页面

- 四职责访问全部保留页面，验证空、载入、正常、错误、无权限和降级六态；
- 验证管理与生产工作区、引擎核心、嵌入、API/事件和离线交付物五种形态；
- 验证 API、Webhook、FHIR/CDS Hooks 风格门面、嵌入、CLI 和 MCP 的真实消费者；
- 按平台管理接入、医疗引擎运行、知识生产、质量管理、第三方接口、专病路径和专业协同七类组合验收，
  证明它们复用统一数据、资产、运行和权限体系；
- 覆盖 HIS/EMR/CDR、LIS/监护、PACS/病理、药房、护理/手麻/输血/ICU、病案医保、公卫院感、
  随访消息、身份源、区域平台、SPD/UDI、科研平台和模型 Provider 的接入或诚实未连接状态；
- 临床调用只提交机构、触发场景和患者事实，不提交发布选择参数；
- 验证患者上下文模型使用边界从前台保存到数据最小化策略表，并证明外部模型路径不会输出患者核心标识明文；
- 验证服务端分页、幂等、traceId、审计和脱敏。

### 5.7 降级、撤回与恢复

- 关闭模型，验证真实 `MODEL_DISABLED` 和 B0 人工/确定性主链；
- 断开图、缓存和代表性外部系统，验证诚实降级、重试和死信；
- 撤回当前危险资产版本，验证新事件停止使用、历史证据仍可重放；
- 回滚机构生效版本，验证规则、路径、术语映射和知识版本同步回退；
- 恢复全部依赖并重新运行关键医学回归。

### 5.8 运维与证据

- 重启服务并确认进程、提交哈希、数据库版本和当前机构生效版本不漂移；
- 执行发布后备份，在隔离库恢复并重放关键临床事件；
- 验证监控、健康检查、告警、审计、证据索引和磁盘清理边界；
- 输出 `launch-coverage.json`，汇总六层产品能力、13 类标准患者资源、13 类版本化资产、
  11 个知识内容分类、完整医疗语义族、全医疗专业领域、S0–S40、五种交付形态、七类业务组合、
  第三方系统族、组织层级、专病十阶段和模型赋能矩阵；
- 汇总逐项覆盖矩阵，每行必须包含前置阶段 `evidenceStage`、`evidencePath`、`evidenceKey`、
  `observedCode`、`observedStatus` 和 `observedAt`；覆盖审计阶段不得自证覆盖，任何 `SKIPPED`、
  `UNKNOWN` 或未解释失败都不能判定上线通过。
- 输出 `launch.ledger.zero-unknown` 严格归零摘要，逐项记录总账通过/失败、未知、跳过、缺证、
  未解释失败、人工豁免、已分类/未分类缺口计数及四类闭环状态；不得以人工豁免抵消任何非零项。

完整演练通过后执行独立验收：

```bash
  --expected-host <134目标机hostname> \
  --expected-source <40位本地提交哈希> \
  --external-base-url https://<正式域名>/medkernel \
  --provider-code ollama-launch \
  --expected-business-tables <候选模式清单表数> \
  --expected-flyway-version <候选迁移版本> \
  --confirm-restart \
  --confirm-database medkernel
```

独立验收必须从数据库、服务、外部 HTTPS 和证据目录重新核对结果，不得只读取演练脚本的
“通过”标记。最后再次备份演练后数据库，在隔离库恢复并验证关键主体、资产、机构生效版本、患者
资源和执行证据，再删除隔离库。
`--expected-source` 校验运行 manifest/JAR 来源；前端-only 发布不会改写运行 `manifest.properties`，
前端 dist 的来源需用首页 `index`/`assets` 与发布命令 `--source` 另行追溯。

## 7. 证据边界

默认证据目录：

```text
${MEDKERNEL_RUNTIME_ROOT}/evidence/current-launch/
```

证据索引至少包含候选摘要、数据库清单、演练阶段结果、`launch-coverage.json`、S0–S40 覆盖矩阵、专业领域矩阵、
13 类资源矩阵、13 类资产矩阵、11 类知识矩阵、完整语义矩阵、专病十阶段、模型赋能矩阵、
五种交付形态、七类业务组合、组织层级、第三方系统、两机构差异、机构生效版本、降级、回滚、
重启和恢复结果。

目录只允许脱敏 JSON、文本摘要和必要的本次演练截图。凭据、Cookie、JWT、患者明文、模型密钥、
首次接管令牌和恢复码不得进入证据。模型外调证据只保存字段清单、脱敏后摘要、责任确认引用和目标
Provider，不保存脱敏前患者上下文。仓库不提交运行截图、原始业务数据或服务器凭据。
