## 1. 这页给谁干什么

质控改进给质控办、医务处、科主任和院级管理者使用。目标是把随访、提醒、路径和评估结果转成可复核的质控问题，并推动责任科室提交整改证据，最终在驾驶舱看到闭环状态。

本章覆盖五类入口：

| 页面 / 接口 | 入口 | 用途 |
|---|---|---|
| 智能随访 | `/clinical/followup` | 查看出院随访计划、任务、问卷和异常返院 |
| 评估指标库 | `/qc/eval/sets` | 建指标、提交审核、发布灰度、等待管理员全量激活 |
| 评估结果 | `/qc/eval/results` | 查看评估运行、达标结果、质控问题和整改任务 |
| 质控预警 | `/qc/alerts` | 查看高风险质控问题生成的预警并确认处理 |
| 质控驾驶舱 | `/qc/dashboard` | 看科室热力图、整改闭环率、价值指标和下钻证据 |

浏览器入口不带 `/medkernel` 前缀；后端 API 统一在 `/medkernel/api/v1/*`。

## 5. 七步流操作

| 步骤 | 操作 | 通过信号 |
|---|---|---|
| 1 | 医生在智能随访入口为 CAP 患者创建出院随访计划 | 生成 7 天电话问卷和门诊复评任务 |
| 2 | 护士提交症状问卷 | 问卷状态 `COMPLETED`，随访统计完成数增加 |
| 3 | 护士上报异常返院并回流结果 | 生成异常返院事件和新标准上下文快照 |
| 4 | 质控办创建两项指标并提交发布 | 指标完成 `DRAFT -> PENDING_REVIEW -> PUBLISHED -> GRAY` |
| 5 | 医院管理员全量激活指标 | 指标进入 `ACTIVE`，旧同编码激活版本自动下线 |
| 6 | 质控办运行评估并查看结果 | 生成 2 条结果、1 条 P1 问题和 1 个整改任务 |
| 7 | 科主任提交整改，质控办复核关闭 | 整改任务 `CLOSED`，驾驶舱闭环数更新 |

## 6. 权限边界

| 角色 | 能做什么 | 幕7结果 |
|---|---|---|
| 呼吸科医生 | 创建随访计划、查看回流上下文 | 已拥有 `followup.write` |
| 呼吸科护士 | 提交问卷、上报异常、回流随访结果 | 已拥有 `followup.write`，创建质控指标被 403 拦截 |
| 医务处 | 观察质控入口和结果，不直接运行评估 | 没有 `evaluation.execute`，脚本改由质控办执行 |
| 质控办 | 建指标、发布灰度、运行评估、复核整改 | 拥有 `evaluation.write/publish/execute/remediate/review` |
| 医院管理员 | 全量激活指标 | `activate` 仅管理员可执行 |
| 科主任 | 提交本科室整改证据 | 拥有 `evaluation.remediate` |

## 7. 六态与异常处理

| 状态 | 质控页面怎么处理 |
|---|---|
| 加载中 | 显示当前筛选和加载状态，不清空上一次结果 |
| 空结果 | 明确说明当前科室 / 状态 / 时间窗无记录 |
| 错误 | 显示 traceId 和可重试入口，保留用户输入的筛选条件 |
| 无权限 | 告诉用户需由哪个角色处理，例如全量激活需医院管理员 |
| 部分可用 | 价值指标缺少责任科室字段时显示 `NOT_AVAILABLE`，不填 0 冒充好转 |
| 成功 | 展示问题、预警、整改和驾驶舱下钻证据的闭环链路 |

常见处理：

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 护士不能建指标 | 护士只有随访执行权限 | 保持拦截，质控指标由质控办配置 |
| 医务处不能运行评估 | 医务处没有 `evaluation.execute` | 改由质控办运行，医务处查看结果 |
| 质控办不能全量激活 | 全量激活是医院管理员边界 | 质控办发布灰度后交管理员激活 |
| 驾驶舱某些指标不可用 | 缺少责任科室或时间窗 | 显示 `NOT_AVAILABLE` 和原因，不显示 0 |
| 待办/通知没有同时出现 | 随访异常聚合尚未统一 | 记录为体验重构点，不伪造成已触达 |
