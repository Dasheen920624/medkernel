## 2. P2 产品门禁任务目录

1. 全量盘点前端路由、页面、后端菜单、控制器、批量任务、第三方接口和专家能力。
2. 为每项能力给出且只给出保留、重命名、移位、合并、拆分、专家化、接口化或移除裁决。
3. 比较候选信息架构，锁定五大主域和入口承载规则。
4. 重构前后端菜单、路由、权限、面包屑和客户名称。
5. 按机构治理、知识配置、临床协同、质量与运营重构页面任务。
6. 清理客户可见英文枚举、技术对象和阶段性术语。
7. 建立 14 角色默认工作台、菜单快照和主任务旅程。
8. 完成桌面/移动端全页面可打开性、六态和八视角评审。
9. 将“平台知识文献资料库根地址”纳入配置中心：键 `medkernel.knowledge.literature.material-root-uri`，初始状态为“未配置”；正式地址不得硬编码当前服务器 IP 或存储厂商，也不得写入 yml，必须由系统配置页维护。后端兼容 COS/S3/OSS/OBS/MinIO/HTTPS 网关等受管 URI，并拒绝 `tmp`、`file://`、非加密 HTTP；未配置时不得启动正式知识生产。
10. 跑前后端全量测试、构建、T-GATE、五方言门禁并提交。
11. 更新 `docs/_HANDOFF.md`、产品门禁验收报告和精简上下文快照。

详细实施步骤见 [全系统功能与产品信息架构重构实施计划](2026-06-11-global-product-ia-refactor-implementation.md)。

## 3. P3–P5 发布与双演练任务目录

1. 核验目标主机、部署目录、数据库实例、当前版本和回退路径。
2. 生成数据库、配置、制品和关键证据备份；记录摘要、时间、操作者和恢复命令。
3. 在隔离恢复目标验证备份可读，不以“命令成功”替代恢复证据。
4. 清理旧库并按五方言全新基线从零迁移，不执行历史兼容脚本。
5. 发布前后端与运行依赖，验证健康检查和诚实降级。
6. 首轮按 14 角色从前台完成配置、维护、审批、处理和查看；只允许 API 模拟外部系统或铺设无关前置。
7. 登记问题、复现、定根因、写失败测试、修复并重跑相关门禁。
8. 从干净基线执行第二轮完整重演，不复用首轮业务结果冒充通过。
9. 完成备份恢复、全角色、医疗安全、数据最小化、全链路、浏览器、部署和 GA 门禁。
10. 在系统配置页复核“平台知识文献资料库根地址”指向正式受管资料库根，且未使用 `tmp`、服务器本地临时目录或非加密 HTTP。
11. 形成第一阶段正式验收报告、接力和精简上下文快照，并冻结 134 平台知识结构作为 P6 唯一生成目标。

## 5. 上下文与接力规则

- 每个阶段结束只在对应验收报告记录完整证据；`docs/_HANDOFF.md` 只保留当前状态、阻断、关键提交和下一步。
- 阶段快照统一写入 `docs/audit/context-snapshots/`，内容限定为权威输入、已完成、未完成、证据命令、风险和下一步。
- 新阶段开始前先读取最新快照和 `_HANDOFF.md`，不回读旧会话过程。
- 长目标持续绑定当前 Codex 会话；需要收缩上下文时只在本会话内压缩整理，不创建、切换或引导用户进入新线程，也不得用上下文整理掩盖未通过门禁。
- 所有平台知识生成只允许发生在当前指定的 134 主平台知识管理服务器；生成前必须确认功能验收全绿、结构冻结、第一阶段正式验收通过，并确认“平台知识文献资料库根地址”是正式受管资料库根而非 `tmp` 或服务器本地临时目录。该根地址不硬编码服务器 IP 或存储厂商，迁移主机或更换存储时通过系统配置页维护。
