# 第二阶段 P2-A 模型底座实现计划（LLM-03 + LLM-08 + LLM-07）

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:executing-plans 逐任务实现（同会话 TDD 红绿）。步骤用 `- [ ]` 复选框追踪。
> 读卡前置：[核心 CONSTITUTION](../../CONSTITUTION.md) + [wave2 _brief §第二阶段设计校正](../../cards/wave2/_brief.md)。三卡：[LLM-03](../../cards/wave2/LLM-03.md) · [LLM-08](../../cards/wave2/LLM-08.md) · [LLM-07](../../cards/wave2/LLM-07.md)。

**Goal:** 把现有「无 provider 恒 B0」的模型能力网关，升级为「有 provider 真增强 / 无则诚实 B0」，并用出域数据最小化闸（LLM-03）和医学回归评测闸（LLM-07）双闸把住 provider 上线，全程恪守铁律 #1 真实性 / #2 诚实降级 / #4 B0 先于模型。

**Architecture:** 在 `engine/llm` 包内，于 `ModelGatewayService.submitTask()` 第 4 步（现恒走 `executeB0Fallback`）插入「闸 → provider → 闸」链路：① 解析路由策略与部署形态；② B2 外部调用前过 `ModelEgressGuard`（白名单+脱敏+审批+阻断+证据）；③ 经 `ModelProviderRegistry` 取已上线且健康的 provider 适配器真实调用；④ provider/版本上线前必须由 `MedicalRegressionEvaluator` 评测 PASS（高危能力另需专家复核签字）。任一闸不过或 provider 缺位/断连 → 诚实降级 B0，绝不伪造模型名/置信度/引文。新增「部署形态」配置（`PRODUCTION_CENTER` 外网生产中心可用 B2 / `HOSPITAL_RUNTIME` 内网运行禁外部 provider），默认取最严格的 `HOSPITAL_RUNTIME`。

**Tech Stack:** Java 21 / Spring Boot 3 / Spring Web `RestClient`（provider HTTP，经接口注入便于 TDD mock）/ Flyway 五方言（postgres·h2·oracle·dm·kingbase，下一号 V124）/ JUnit5 + Mockito / Jackson。

## 锁定的设计决策（执行不可偏离）

1. **双形态判定**：新增系统配置键 `medkernel.deployment.form`（`SystemConfigService.DEPLOYMENT_FORM_KEY`），值 `PRODUCTION_CENTER` | `HOSPITAL_RUNTIME`，由 `SystemConfigSeeder` 以**默认 `HOSPITAL_RUNTIME`（最严格安全默认）**种入；134 生产中心显式配 `PRODUCTION_CENTER`。新建 `DeploymentFormService` 读配置。`HOSPITAL_RUNTIME` 下注册/启用 B2 外部 provider 一律拒绝，运行任务遇 `EXTERNAL_MODEL` 路由 → 诚实降级 B0。
2. **provider 凭据不落明文**：`model_provider.credential_ref` 只存密钥引用（key id），真实密钥走既有凭据管理（`engine/security` 的 `PlatformCredential`/`CredentialAdminService`），适配器调用时按 ref 解析，绝不落库明文、绝不进日志/审计摘要。
3. **provider 真实产出复用既有 schema 校验**：provider 返回内容仍走 `validateSchema`；真实产出写真实 `model_mode`(B1/B2)/`model_version`/`confidence`/`source_citations`，B0 路径保持现状不动。
4. **新错误码**（追加到 `ErrorCode`，005 已占用=敏感未脱敏）：
   - `ENG_LLM_006`（422）出域字段超白名单/未脱敏被阻断
   - `ENG_LLM_007`（403）B2 高敏出域未经审批被阻断
   - `ENG_LLM_008`（409）provider/版本未过医学回归评测，禁止上线
   - `ENG_LLM_009`（400）当前部署形态禁用外部 provider（运行侧内网）
5. **新权限码**（按 14 角色矩阵 §9 落点，ACTION 维度）：
   - `llm.provider.manage`（集成运维员 O2）配 provider/凭据引用
   - `llm.egress.manage`（合规审计员/安全，O4/O13）配出域白名单 + 审批出域
   - `llm.eval.manage`（质量与医保治理员 O6）配基准集 + 跑评测 + 复核签字
   - 三码经迁移 INSERT 五方言 + `DefaultPermissionPolicy` 授权 + **同步两处断言** `PermissionDimensionModelTest` + `DefaultPermissionPolicyTest`（[ref-permission-menu-two-test-sites]）。
6. **迁移分号**：V124=`model_provider`；V125=出域三表（`model_egress_whitelist`/`model_egress_approval`/`model_egress_evidence`）；V126=评测两表（`medical_regression_case`/`model_eval_run`）；V127=三权限码 INSERT。各五方言（postgres/h2 用 TIMESTAMPTZ·BIGSERIAL；oracle 用 VARCHAR2·NUMBER·GENERATED BY DEFAULT AS IDENTITY·INSERT ALL…SELECT 1 FROM DUAL；dm/kingbase 仿 oracle/postgres，按现有 V18/V123 同表对照写）。
7. **TDD 边界**：provider 适配器的 HTTP 经 `ModelProviderHttpClient` 接口注入，单测注入 fake，杜绝真连外网；真实性门禁（无 provider 不伪造）用反例断言锁定。

## 子系统二：LLM-08 provider 真实接入（任务骨架，落 LLM-03 后细化为 bite-sized）

- **T7 部署形态**：`DeploymentFormService` 读 `medkernel.deployment.form`；TDD：默认 `HOSPITAL_RUNTIME`；配 `PRODUCTION_CENTER` 时 `allowsExternalProvider()=true`。改 `SystemConfigService`+`SystemConfigSeeder`。

- **T9 provider 抽象 + 注册表**：`ModelProvider` 接口 + `ProviderType`(OLLAMA/OPENAI_COMPATIBLE/CLAUDE/DIFY) + `ModelProviderRegistry.resolve(routeStrategy, capability, tenant)`；TDD：LOCAL_MODEL→OLLAMA、EXTERNAL_MODEL→B2、无配置→empty。
- **T10 适配器**：`OllamaProvider`/`OpenAiCompatibleProvider`/`ClaudeProvider`（注入 `ModelProviderHttpClient`）；TDD：fake http 返真 JSON→真实 completion；http 异常→`ProviderHealth.NOT_CONNECTED`。凭据按 `credential_ref` 解析，绝不落明文。
- **T11 健康检查**：`checkHealth()` 探活；注册表过滤不健康 provider。
- **T12 submitTask 接线**（改 `ModelGatewayService` 第 4 步）：TDD 反例锁定——
  - 有健康 provider + 过出域闸 + 过评测 → 真实 `model_mode`/`model_version`/`confidence`/`citations`；
  - 无 provider/断连 → 诚实 B0（现有断言不破）；
  - `HOSPITAL_RUNTIME` 形态 + `EXTERNAL_MODEL` → 抛 `ENG-LLM-009` 后诚实降级 B0；
  - B2 出域必先过 `ModelEgressGuard`（越界→ENG-LLM-006）。
- **T13 provider 控制器**：`ModelProviderController`（`llm.provider.manage`）配 provider；激活前校验已过评测（接子系统三）。错误码 008/009。
