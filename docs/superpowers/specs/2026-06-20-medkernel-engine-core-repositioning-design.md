# MedKernel 引擎核心重定位 · 总设计（防偏差唯一锚点 · v2）

> 日期：2026-06-20 ｜ 状态：设计待批 ｜ 作者：用户决策 + Claude
>
> **v2 变更**：按用户定调收敛安全/闸门模型——生产期全自动工程化，仅在「真实上线前」由专家做一次全面审核，运行期引擎纯辅助、默认不阻断。删除之前的逐条审核 / 双签 / 九闸（正是它们把进度卡死、把知识憋成 0、把系统弄乱）。同时改为**清库全新重建、零兼容旧技术债**。
>
> **本文目的**：把 MedKernel 从「面向医院的多租户临床 SaaS」重定位为「医疗引擎核心」，并给出一份**任何 AI 实现者照着做都不会跑偏**的目标设计。当前系统乱，根因是定位偏差 + 闸门过多 + 多份文档互相打架、没有唯一锚点。本文就是那个锚点。
>
> **权威关系**：本文一经批准即为引擎重构的**顶层目标**，要求同步修订 [CONSTITUTION](../../CONSTITUTION.md) §0/§2/§6/§8/§15（见 §15）。与旧卡/旧文档冲突时，以「本文 + 修订后宪法」为准，被保留的卡降为下级实现细节。

## 1. 产品定位（拟改宪法 §0）

**MedKernel 医疗引擎核心**：

> 一套自主生产权威医疗知识、并把这些知识以 11 个能力，通过 **API + 页面嵌入两种模式供给业务系统（HIS / EMR / CDSS）**的医疗引擎。平台自带「引擎能力控制台」，可在平台内演示与验证全部能力。

- 引擎是产品**主体**。「集团医疗智能中枢 / 医院七业务域 / 临床医生护士直接登录用」那一层**降为引擎的使用场景**（临床终端经 API 或嵌入消费，不在本系统登录做临床工作）。
- 「集团化 / 平台主权 / 多客户 / 内外网」**全部保留**，用**组织范围 + 环境维**承载，不靠堆角色（见 §7）。
- 中文产品名本轮统一用「**医疗引擎核心**」（英文 / 代码名仍为 `MedKernel`）。

## 1.5 关键定义与全局原则

- **真实上线** = **院内部署** 或 **外网租户正式启用**（开始面向真实患者）。在此之前一律视为开发 / 演示 / 集成期。
- **单检查点安全模型**：生产期全自动；**仅在「真实上线前」由专家一次性全面审核**要上线的知识与规则；运行期引擎纯辅助。除此之外**不设各种人工闸**。
- **自动化默认 · 零学习成本**：必须保留但**不是用户决策**的能力一律**自动默认 / 隐藏**，不暴露配置项、不给用户增加学习成本；用户面只留真正需要他决定的东西。
- **工程化优先**：能自动判定的用确定性规则 / 测试判定，不引人工；人工只在「真实上线前一次专家审」这一处。

## 2. 不变量（永不简化 · 但都不是拖慢你的「闸」）

下列是重构中**不得触碰**的底线。注意：**它们都不是逐条人工闸**，而是元数据 / 安全 / 数据正确性 / 上线前一次审——不拖慢迭代。来自宪法 §7/§8/§11/§13 与国情合规。

| # | 不变量 | 实现含义 |
|---|---|---|
| R1 | **AI 内容明显标识** | 模型产出带 `aiGenerated=true` 与「AI 生成」文案（生成式 AI 管理办法 §7）。免费元数据，不阻塞 |
| R2 | **来源 100% 可追溯** | 每条知识可回溯 来源类型/标题/版本/引用位置/hash，证据分级 A–E。免费元数据 |
| R3 | **引擎纯辅助** | 引擎**默认不打扰**、**不替业务系统自动下医嘱/写病历/上报/支付**；命中规则按打扰梯度（5 档：静默→硬停）渲染，仅「硬停」无条件拦（见 §9），**无引擎强制双签**，零业务耦合 |
| R4 | **上线前一次专家总审** | 真实上线（院内部署/外网租户）前，由真人医学专家**一次性**全面审核要上线的知识/规则；**不伪造**、自动化不冒充。这是**唯一**人工医学介入；上线前的开发/演示期不需要专家 |
| R5 | **唯一权威知识 + 原子替换** | 同一适用域同时只有一个 `ACTIVE` 版本；新版生效原子失效旧版，旧版仅历史重放（数据正确性，非人工闸）|
| R6 | **关系库权威** | 业务事实唯一权威源是关系数据库；图库/模型/缓存只是可重建投影 |
| R7 | **无模型可运行（B0 先于模型）** | 关掉模型，主链路用 B0 确定性仍可跑通 |
| R8 | **诚实降级 · 不伪造** | 缺模型/连接时返真实状态（`B0`/`NOT_CONNECTED`/`MODEL_DISABLED`），绝不假闭环、不造哈希/调用结果/随机数 |
| R9 | **平台主源不污染** | 平台主租户 `t-1` 是知识唯一主源；客户只读订阅 + 本地覆盖，禁止反写主源 |
| R10 | **真实性门禁 T-GATE** | 前端 no-page-mock + stylelint；后端禁 Math.random 造数/吞错返成功/UUID 充哈希；前后端全绿才算完成 |
| R11 | **国情合规** | 等保 2.0 三级 + 国密 SM2/3/4 + 个保法 + 数据出境合规；敏感字段脱敏 + 字段级加密 + 审计链 |

**口诀**：删的是「闸」（逐条审/双签/九闸）；留的是「元数据 + 安全 + 数据正确性 + 上线前一次审」。

## 3. 系统全貌（一条脊 + 一套运行时）

```
              ┌──────────── 产（全自动·工程化）────────────┐
 公域网/院内 → 获取 → 候选(B0/模型) → 技术质量闸(全自动) → 入库激活(ACTIVE)
              └────────────────────────────────────────────┘
                                   │
                            知识库（版本化 / 唯一 ACTIVE / 来源可溯）
                                   │
              ┌──────────── 供 + 演（同一套运行时）────────────┐
              │  API / 嵌入 ──→ 业务系统(HIS/EMR/CDSS)         │
              │  演示台(同 API/嵌入，抑制副作用) ──→ 平台内验证 │
              └────────────────────────────────────────────┘
                                   │
                  包分发 ──→ 平台/客户 · 内网/外网 运行时
              ╳ 真实上线前：专家一次性全面审 → 放行 go-live
```

1. **一条脊**：产 / 供 / 演 / 管是同一个「知识 + 状态」的不同视角，不是四个系统。
2. **供 = 演**：演示台就是引擎拿自己的 API/嵌入、抑制副作用跑一遍，演示永远等于真实。
3. **生产全自动**：无逐条人工审；技术质量闸是确定性自动判定。人工医学审只发生一次——真实上线前。

## 4. 十一大能力（具体定义 · 输入/输出/例子）

引擎对外只有 **11 个能力**。其余一切（领域门面、KNOWGEN…）都是这 11 个之上的**内容**，不是之外的引擎。每个能力走统一「上下文输入 → 结构化输出 + 来源 + 状态标识」契约。

| # | 能力 | 输入 | 输出 | 例子 |
|---|---|---|---|---|
| C1 | **知识查阅** | 一个医学对象（检验/药/诊断/术语/编码）| 权威知识说明 + 来源 + 标识 | 「血常规」→ 各指标(WBC/Hb/PLT)、参考范围、升降临床意义、出处 |
| C2 | **规则拦截** | 一张医嘱/处方/临床事件 + 患者上下文 | 风险提醒（5 档打扰梯度：静默→硬停）+ 触发依据 | 「华法林+阿司匹林」→ DDI 出血风险提醒 |
| C3 | **专病路径** | 一个**已确诊**病种 + 患者状态 | 标准诊疗步骤 + 关键时间点 | 「社区获得性肺炎(已确诊)」→ 路径 |
| C4 | **字典映射** | 医院本地写法（「白细胞/WBC」）| 标准编码 + 置信 + 高危近似判别 | 院内项 → LOINC，钾/钠高危近似强制 HIGH |
| C5 | **来源追溯** | 一条知识/一次结论 | 出处链：类型/标题/版本/引用位置/hash/分级 | 点开 →「WHO 某指南 第46页 / 版本 / sha256」|
| C6 | **包分发** | 一批已发布知识 + 目标 | 版本化包，发布到平台/客户、内/外网 | 平台发基础包给各医院；内网离线导入 |
| C7 | **获取生产** | 已审批来源（公域网 URL/院内上传）| 抓取→解析→锚定→候选 | 从 WHO IRIS 抓 PDF 解析成候选 |
| C8 | **辅助诊疗（鉴别+推荐）** | 患者症状/体征/检验（**未确诊/普通病**）| 鉴别诊断候选 + 检查/治疗推荐 + 来源 | 「发热+咳嗽+白细胞↑」→ 鉴别(肺炎/流感/支气管炎)+查胸片/CRP |
| C9 | **病历质控/内涵质控** | 一份病历 / 一次诊疗过程 | 缺陷清单 + 依据 + 整改建议 + 评分 | 出院病历 →「缺上级查房、主诊断与编码不符(DRG)、未落实院感」|
| C10 | **随访** | 出院/慢病患者 + 病种/路径 | 随访计划(时点/项目) + 到期提醒 | 「2 型糖尿病出院」→ 复查/HbA1c 3 月/并发症筛查 |
| C11 | **报告解读** | 一份检验/影像报告 | 异常项 + 临床意义 + 建议 | 血生化报告 → ALT↑/肌酐↑ 意义 + 复查/转诊建议 |

> **能力分四类**：知识层 C1/C4/C5；辅助诊疗·质控决策层 C2(事前拦单)+C3(已确诊流程)+C8(未确诊鉴别推荐)+C9(事后评病历)+C10(纵向随访)+C11(报告解读)；生产分发层 C6/C7。
> **防膨胀红线**：能力封顶 11。新需求一律作为「内容/指令」挂到现有 11，复用既有引擎（FOLLOW-01/REPORT-01/CDSS-01/EVAL-01…），**禁止另起状态机/表/页面、不开第 12 个引擎**。

**统一约束**：
- 所有输出带 `status`（§6）、`source`（R2）、`aiGenerated`（R1）。
- 引擎默认**只给建议、不阻断**（R3）；高风险只标注，不强制业务动作。
- 阻断仅在被配置为 L3（填理由放行）/ L4（硬停）的规则发生；L0–L2 不阻断。见 §9。

## 5. 知识资产模型（唯一实体）

全系统只有一种受治理实体：**知识资产**。术语、说明书、规则、路径、计算器、字典项、专病包……都是它的资产类型，共用同一信封：身份 + 版本 + 来源 + 状态 + 适用域。

- 唯一权威：同一适用域同时只有一个 `ACTIVE`（R5）。
- 可复现：`来源 + 生产配置版本 → 同一内容 hash`，支撑 R2 来源可溯与 R10 真实性。
- 资产类型可扩展，但共用信封 + 状态机 + 版本/来源/包/运行服务，不另起炉灶。

## 6. 知识状态机（一套 · 生产全自动）

```
草稿 → 候选 → [技术质量闸·全自动] → ACTIVE(已激活·可用) → 已下线 →(已归档)
                                      ↑
                       真实上线前：发布包级「专家一次性总审」放行
```

| 状态 | 含义 | 进入条件 | 谁/什么推进 |
|---|---|---|---|
| 草稿 | 编著中 | — | 知识生产 |
| 候选 | 待自动闸 | 提交 | 知识生产 / 系统 |
| ACTIVE | 已激活·可被查阅/运行/演示 | **过技术质量闸（全自动）** | 系统自动 |
| 已下线 | 退出，仅历史重放 | 被新版原子替换 | 系统/运营 |

- **技术质量闸（全自动·取代旧九闸）**：schema 校验 + 红线结构完整 + 来源齐全可溯 + 重复检测 + 可复现 hash。全过即自动 ACTIVE，**无逐条人工审**；**未过则留在「候选」并附失败原因、可修复重提，不自动 ACTIVE、不静默丢弃**（R8/R10）。
- **真实上线前**：对「一个客户要上线的知识/规则集」做**一次**专家总审，通过则该**发布包**标记 `expertReviewed=true` 方可 go-live（R4）。这是发布包级、一次性的，不是每条知识的闸。
- 开发/演示期的 ACTIVE 知识照常带 AI 标识与来源；演示台/集成可直接用，因为此时无真实患者。

## 7. 角色与权限模型（权限 × 范围 × 环境 · 5 预设）

**原则**：角色 = 权限**预设包**；平台/客户用**组织范围(scope)** 承载，内/外网用**环境维(env)** 承载。集团化 / 平台主权 / 多客户 / 内外网全靠这两轴，不堆角色码。

逐条审核与双签已删，职责角色收敛为 **5 个**：

| 预设角色 | 职责 | 范围 | 吃掉旧的 |
|---|---|---|---|
| 内置超管 | 系统兜底（§1#20 强制内置、不可降权/旁路、MFA、独立审计）| 仅平台 | system-superadmin |
| 运营管理 | 机构/账号/接入/Provider/配置/运行保障/国产化 | 平台 或 客户 | 平台治理·机构·人员访问·集成·实施 5 个 |
| 知识生产 | 跑获取、跑生产、编著候选（生产全自动入库，无需人工审）| 平台 或 客户 | 平台知识·机构知识 |
| 独立医学专家 | **仅真实上线前**做一次性全面审核（R4）| 平台 或 客户 | 质量医保·药事（签字职责）|
| 合规审计 | 只读查审计与证据 | 平台 或 客户 | compliance-auditor |

- 「知识审核」不再是独立角色——技术审是**自动质量闸**，医学审是**上线前一次专家总审**。
- 被移除的登录角色：临床决策使用者 / 护理 / 医技 / 临床治理 / 质量医保运行侧等 → 改为业务系统经 API/嵌入消费。

## 8. IA（菜单 · 4 个一级入口）

| 一级 | 干什么 | 主要二级 |
|---|---|---|
| **工作台** | 一屏看引擎状态 | 知识总数/激活数、生产流水线、Provider/模型健康、上线就绪 |
| **知识生产（产）** | 把知识做出来（全自动）| 获取来源 · 生产任务(流水线可视) · 来源与血缘 · 模型 Provider · **上线前专家总审** |
| **引擎能力（供+演）** | 用知识、演知识 | 引擎能力控制台(演示台) · 查阅 · 辅助诊疗 · 规则拦截 · 专病路径 · 病历质控 · 随访 · 报告解读 · 字典映射 · 来源追溯 · 对外 API/嵌入接入 |
| **系统治理（管）** | 水电 | 账号与角色 · 审计与证据 · 安全与配置 · 国产化自检 · 开发者控制台 |

约束沿用宪法 §2 / 体验契约：一页一目标、主按钮 ≤1、默认筛选 ≤3、六态、服务端分页、左侧主菜单。**非用户决策项一律自动默认/隐藏**（§1.5），不堆配置。

## 9. 对外供能契约（两种交付模式：API + 页面嵌入）

引擎对外有**两种交付模式**，红线 R1–R11 两种模式下都成立：

- **API 模式**：业务系统调接口、自己渲染。
- **页面嵌入模式**：引擎给**可嵌入 UI 片段**（iframe / Web 组件 / SMART on FHIR / CDS Hooks 卡片），直接嵌进 HIS/EMR，业务系统**不用重做界面**。底座 EMBED-01 + API-11。

| 能力 | 端点（既有卡）|
|---|---|
| C1 查阅 | 知识 API（API-03）|
| C2 规则拦截 | 推荐/CDSS（API-07）+ CDS Hooks（OPT-02）|
| C3 专病路径 | 路径 API（API-06）|
| C4 字典映射 | 字典 API（API-04）|
| C5 来源追溯 | 来源追溯（PROV-01）|
| C6 包分发 | 包发布 API（API-10）|
| C7 获取生产 | 获取编排（acquisition）+ 文档解析 |
| C8 辅助诊疗 | 推荐/CDSS（API-07 · CDSS-01）+ 鉴别（KNOWGEN-17）|
| C9 病历质控 | 评估质控（API-08 · EVAL-01）+ 病案医保（SVC-QUALITY-02）|
| C10 随访 | 随访 API（API-09 · FOLLOW-01）|
| C11 报告解读 | 报告解读（REPORT-01）+ CDSS（API-07）|

**运行期打扰模型（关键 · R3）**：
- **默认：纯辅助、不打扰**。无规则命中即静默，不影响业务系统运行。
- 命中规则时按**打扰梯度**渲染，**5 档从轻到重、逐规则可配**（对齐宪法 §6 并细化，防警报疲劳）：

| 档 | 代码 | 行为 | 是否阻断 |
|---|---|---|---|
| L0 | `SILENT` | 静默 / 旁路：不弹窗，只记录 + 角标 / 侧栏标注，医生想看才看 | 否 |
| L1 | `INFO` | 提醒 / 告知：弹窗或卡片告知，可直接关闭继续 | 否 |
| L2 | `ACK` | 需知悉：必须点「已知悉」才继续，仍不阻断业务 | 否 |
| L3 | `REASON` | 填理由放行：医生填理由后执行，理由留痕 | 软（可过）|
| L4 | `HARD_STOP` | 硬停 / 真阻断：返回硬停信号，业务系统 / 嵌入按合同阻断该医嘱 | 硬（不可过）|

- 呈现位置、是否「稍后提醒」按档默认，不另设档。**无引擎强制双签**，不增业务耦合。是否打扰、到哪档，全由**规则配置**决定，引擎不统一强加。

统一：FHIR R4/R5 + CDS Hooks 门面、标准上下文（API-01）、健康检查/重试/死信/回放、断连诚实 `NOT_CONNECTED`（R8）。

## 10. 演示台（= 对外 API/嵌入 + 沙盘）

- 演示台**不是**独立引擎，是个 UI：选真实场景 → 调**同一套 API/嵌入**、抑制外部副作用（沿用沙盘 CURRENT/HISTORICAL_EXACT/COMPARE）→ 同屏亮起各能力结果，每条可点开看证据。
- 可并排显示「原始 API 响应 ↔ 医生可读提醒 ↔ 嵌入组件实时预览」，API 与嵌入两种模式现场可见。
- **场景库**：4–5 个真实场景（用药安全/急危重症/质控/字典…）覆盖全部能力 + 一张能力覆盖清单。
- 散件（沙盘/CDSS 疲劳/各页「试一下」）**收口**进演示台，不重造。
- 显示真实状态与标识，不美化、不造数（R8）。

## 11. 知识生产模型（全自动 + 上线前一次审）

- **生产全自动**：`获取 → 候选(B0/模型) → 技术质量闸(全自动) → 入库 ACTIVE`。无逐条人工审、无双签、无九闸（这些正是之前让进度慢、系统乱的根源）。
- **B0 先于模型**（R7）：人工编著/权威来源结构化的 B0 即正式知识；模型做增量、产候选，候选同样过自动质量闸入库；模型产出带 AI 标识（R1）。
- **启用 Provider** = 纯技术就绪判定（健康检查 + 技术质量评测），全自动，不需要专家。
- **获取边界**：公域网自主获取只在**平台外网侧**（白名单/HTTPS/许可/robots/拒私网/大小上限）；内网客户不爬外网，靠 C6 包分发。
- **唯一人工点**：真实上线前，专家对该客户要上线的知识/规则做**一次**全面审核，标记发布包 `expertReviewed=true` 才 go-live（R4）。开发/演示/集成期完全不需要专家。
