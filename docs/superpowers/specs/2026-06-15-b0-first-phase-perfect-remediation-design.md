# B0 第一阶段完美化整改设计

## 背景

用户明确要求暂停 wave2 知识生产推进，先把第一阶段 B0 全功能面做到可长期交付。第一阶段 B0 主链路已经通过，但最新审计报告指出：部分人工维护、字段、路径、版本、第三方、角色体验和证据链仍停留在“能演练通过”，尚未达到“真实客户长期使用不踩坑”的标准。

本设计以 [`docs/audit/2026-06-15-B0第一阶段全功能核查与完美化改造方案.md`](../../audit/2026-06-15-B0第一阶段全功能核查与完美化改造方案.md) 为需求源，目标是在一个本地分支上累计整改，最终只提一个大 PR；整改完成前不合入远程 `main`。

## 非目标

- 不进入 P6。
- 不生产 KNOWGEN 首发知识包。
- 不把 AIK-STD-13 PR1 扩成正式知识生产闭环。
- 本轮暂不处理国产化真实数据和真实国产环境验收；相关项只保留不可宣称完成的文档口径。
- 不触碰 134 目标环境，除非用户后续重新授权部署/验收。

## 设计目标

1. 把第一阶段 B0 主线从“已跑通”提升为“可交付、可维护、可审计、可扩展”。
2. 解决用户点名并已核实的高风险问题：诊断维护放在审核页、路径字段可能不生效、上下文字段目录不足以支撑运行和第三方、版本选择不受控、批量维护和质量门禁不闭合。
3. 形成 B0 完美化的自动化验收入口，后续每次继续整改都能复跑同一套证据。
4. 保持所有行为变更 TDD：先写失败测试，再实现。

## 核心改造

### 1. 产品面和路由

`/knowledge/governance` 收敛为“知识审核与发布”，只承载候选审核、差异、发布、驳回、替换和恢复。诊断知识人工维护迁出为独立 B0 维护入口，建议路由为 `/knowledge/diagnosis`，标题为“诊断知识维护”，仍属于“知识治理”一级域，但不再混在审核页。

短期不启用“知识生产”一级域，避免误导为 wave2 正式生产已恢复。等 B0 完美化完成后，再按 wave2 设计接回知识生产工作台。

### 2. 诊断知识可用性

诊断标准中 `valueConstraint` 和 `temporalConstraint` 当前只落库、不求值。整改第一阶段先做安全阻断：只要待发布版本含非空数值或时间约束，而运行求值器尚未支持，发布门禁直接拒绝，并给出明确错误信息。后续再接结构化 predicate 和真实求值器。

同时修复测试用例 `findings` 解析：去除空白项、去重、重复项不抛 500，并将无效输入转为结构化业务错误。

### 3. 路径字段和上下文桥接

保留现有路径 include/exclude 逻辑，新增运行字段桥接层：把字段目录 canonical path 和路径运行时 context facts 显式关联。第一刀至少覆盖 `observations[].valueNumeric`、`observations[].code` 与现有 `observation.<code>.valueNumeric` 形态，补入径纳入、入径排除、出径纳入、出径排除回归测试。

前端字段选择处显示字段的运行支持状态；未支持字段不能悄悄进入发布态。

### 4. 字段目录和第三方契约

字段目录从页面局部维护提升为 B0 数据契约中心的基础模型。第一刀不大改表结构，先扩展响应 DTO 和契约生成信息：运行支持状态、支持引擎、必填策略、空值策略、来源系统/映射说明占位字段。第三方契约输出中必须标注字段是否可运行、哪些引擎支持、缺失时如何降级。

### 5. 包版本选择

逐步消除关键页面中自由输入 `packageVersion` 的使用方式。第一刀优先处理字段契约读取、规则/路径/诊断维护中的显性输入：改为可选包版本列表或从当前有效包解析，并在 UI 展示状态、范围和来源。后端继续保留兼容参数，但前端不鼓励手填。

### 6. B0 完美化验收

新增 B0 完美化验证脚本或测试入口，覆盖：

- 14 角色菜单和主动作不漂移。
- 32 入口页面目标不混乱。
- 知识审核页不再承载诊断维护。
- 诊断复杂约束发布被阻断。
- 路径 canonical 字段能被运行求值。
- 字段契约输出包含运行支持信息。
- 国产化真实环境项被排除在本轮验收外，并在报告中保留不可宣称口径。

## 风险与取舍

- 这是一个大 PR，风险主要来自跨前后端、文档和测试联动。为降低风险，按小切片 TDD 实施，但最终合并为一个 PR。
- 本轮只修 B0 地基，不扩展正式知识生产，避免范围失控。
- 对诊断复杂约束先阻断再实现求值，优先保证医疗安全和诚实状态。
- 国产化真实环境暂缓，避免因外部环境缺失阻塞本轮主线。
