# 平台主源与租户覆盖层设计

## 背景

平台主租户 `t-1` 是医疗知识、规则、路径模板与标准包的唯一主源。主源只能更新 / 同步主源本身；客户、集团、医院租户默认订阅或授权使用平台发布版本，不把平台资产物理同步成客户主源副本。只有在本地新增或修改同一份资产时，才生成本租户覆盖副本。覆盖副本不得反写平台主源，也不能阻断未覆盖资产自动读取平台最新版。

当前代码已经治理了平台主租户唯一性和离线包导入边界，但知识、规则、路径的服务层仍多处直接按当前 `tenant_id` 查询。这会导致客户租户看不到平台新内容，或者后续同步时面临“覆盖客户定制”和“客户数据落后”的两难。

## 目标

1. 平台主源唯一：`PlatformTenant.ID` 固定为 `t-1`，`SYSTEM` 只作为技术命名空间。
2. 有效读取统一：非平台租户读取医疗资产时，先查本租户覆盖，再回退平台主源。
3. 本地编辑隔离：客户、集团、医院修改平台资产时，写入本租户副本，不写平台表行。
4. 平台更新自然生效：未覆盖资产直接读取平台最新版本；已有覆盖资产继续优先生效。
5. 运行日志归属正确：客户执行平台规则或路径模板时，执行事实仍归客户租户。
6. 主源同步限制：平台主源不得同步成客户主源；面向客户的下发只能是只读发布版本、离线快照或订阅引用。

## 范围

本轮第一阶段覆盖三类运行核心资产：

- 标准知识身份与知识版本：`knowledge_identity`、`knowledge_asset_version`
- 规则定义与规则版本：`rule_definition`、`rule_version`
- 专病路径包与路径模板图：`specialty_package`、`pathway_template`、`pathway_node`、`pathway_edge`

推荐后续在第二阶段补充覆盖关系表，记录 `base_platform_version_id`、合并状态和人工 rebase 任务。本轮先使用现有业务编码作为 canonical key，完成正式交互所需的有效读取与写入隔离。离线包导入也要按这个语义收口：平台包进入客户环境时只能成为只读平台发布快照或引用，不得生成客户主源资产行；客户资产行只来自本地新增或明确 copy-on-write 覆盖。

## 方案选择

### 方案 A：全量同步到每个租户

实现简单，但平台更新后需要批量覆盖客户数据；不覆盖会落后，覆盖会污染定制。放弃。

### 方案 B：平台主源 + 租户覆盖层

读取时合并平台和本地，本地同业务编码覆盖平台；本地没有的资产直接使用平台最新版。推荐采用。

### 方案 C：覆盖层物化视图

在方案 B 基础上维护有效资产物化表，性能更好，但迁移和一致性复杂度高。作为后续优化，不作为本轮起点。

## 业务键

本轮用已有字段作为 canonical key：

- 知识：`knowledge_identity.identity_code`
- 规则：`rule_definition.rule_code`
- 路径模板：`pathway_template.template_code + template_version`
- 专病包：`specialty_package.package_code + package_version`

同一个 canonical key 在客户租户存在本地行时，本地行覆盖平台行；否则平台行参与有效结果。

## 读取规则

非平台租户读取列表：

1. 加载当前租户行。
2. 加载平台主源行。
3. 按 canonical key 去重，本租户行优先。
4. 返回合并后的有效资产集合。

非平台租户读取详情：

1. 先按当前租户和业务 ID 查本地资产。
2. 未找到时按平台租户查平台资产。
3. 详情的关联版本、节点、边随主资产来源租户读取。

平台租户读取只读写平台自身，不回退其它租户。

平台主源同步：

1. 平台主源只允许同步到平台主源的发布账本、只读发布快照或同一平台主源环境。
2. 客户、集团、医院只能订阅或导入平台发布快照用于读取，不拥有该资产的主源归属。
3. 客户需要定制时，从平台发布快照生成本租户覆盖副本，副本标记为本地覆盖，不再称为平台同步副本。

## 写入规则

创建新资产：

- 当前租户是平台：创建平台主源。
- 当前租户是客户/集团/医院：创建本地新增资产，仅在当前租户可见。

修改资产：

- 找到当前租户本地资产：只改本地。
- 当前租户未找到但平台有同业务 ID：拒绝直接覆盖平台，要求先创建本地副本或由服务执行 copy-on-write。
- 平台租户修改平台资产：正常修改平台主源。

本轮先保证服务层不会把客户写入误落平台。完整 copy-on-write 自动克隆可在第二阶段按前端编辑流补齐。

## 运行规则

规则执行：

- 候选规则使用有效读取集合。
- 执行平台规则时，规则内容来自平台，但 `rule_execution_log.tenant_id` 必须写当前客户租户。

路径入径：

- 模板有效读取可回退平台。
- 患者路径实例属于当前客户租户。
- 后续推进加载模板图时，若客户本地无模板图，继续使用平台模板图，不要求复制整张图。

离线分发：

- 平台离线包在客户侧作为平台发布快照读取，不自动落成客户主源资产。
- 客户本地已有覆盖时，离线包更新不得覆盖本地覆盖。
- 客户新增或覆盖资产不得打包回写为平台主源，除非走平台审核吸收流程。

## 前端体验

列表页应展示来源状态：

- 平台标准
- 本地覆盖
- 本地新增

本轮后端先保证有效数据可用；前端可在后续基于响应扩展来源标签与“恢复平台标准 / 合并平台更新”操作。

## 测试策略

1. 知识：客户租户按身份读取时，本地没有则回退平台；本地有同 `identity_code` 时覆盖平台。
2. 规则：客户租户执行时可使用平台已发布规则；同 `rule_code` 本地规则优先；执行日志归客户租户。
3. 路径：客户租户可基于平台已发布模板入径；同 `template_code + version` 本地模板优先；运行时事实归客户租户。
4. 平台租户：不读取客户副本，不被客户写入污染。
