# #647 医疗引擎中枢上线收缩设计

## 1. 目标与基线

本设计只以 PR #647 合并提交 `acd511c0` 为代码基线，不读取、复用或比较 #648、#649 的方案。

本轮不是删除引擎能力，也不是重写系统，而是把当前“引擎核心、SaaS 管理、临床工作台、质量管理、模型生产治理”混杂的默认产品面，收缩为可直接部署和运营的医疗引擎中枢。

完成后的系统必须满足：

1. 默认用户只看到完成中枢运营所需的功能；
2. 默认只分配少量稳定职责，不要求尚不存在的专家委员会或多层组织角色；
3. MFA 默认关闭，可由配置中心显式开启；内置超级管理员仍保持强制 MFA；
4. 低、中风险知识由知识运营职责完成单签，医疗高风险知识继续双签并在缺少合格人员时诚实阻断；
5. 模型是可选增强能力，不是引擎启动、接入、受控来源初始化和低风险知识发布的全局前置条件；
6. 临床协同、质量管理、租户开通等既有 API 和页面代码保留为隐藏或嵌入能力，不进入首发中枢主导航；
7. 清库部署后可以自动建立少量来自受控官方原件、非模型生成、非诊疗建议的 LOW 正式权威知识，并走真实来源批准、候选审核、激活、追溯和运行读取链路。

## 2. 已核查事实

### 2.1 规模与基线

- 后端 95 个 `@RestController`，迁移版本 V159，五方言迁移目录完整；
- `@PreAuthorize` 约 501 处，说明底层能力授权已经形成，不应以“简化”为由整体拆除；
- 当前 14 个客户可分配角色、115 个权限编码、32 个主菜单；
- 当前前端 8 个一级域，同时暴露机构人员、知识治理、知识生产、临床协同、质量管理、合规安全和系统运维；
- MFA 策略把 11 个角色硬编码为必须绑定；
- 模型生产控制台把 Provider、评测、独立复核、九项门禁和生产串成全局主链；
- 候选路由按临床、药事、医技、质量等角色分派，现实开发阶段没有对应专家人员；
- 基础初始化已有真实来源、来源独立批准、候选冻结、LOW 批审和状态机能力，但原清单固定生成 `MEDIUM / PENDING_AUTHORING` 骨架，不能形成正式激活知识。

### 2.2 绿基线

- 后端：3131 tests，0 failures，0 errors，2 skipped；
- 前端：106 个测试文件，830 tests 全绿；
- CLI：30 tests 全绿；
- MCP：16 tests 全绿。

所有后续实现必须在该基线上用 TDD 演进。

## 3. 根因

当前混乱不是单个页面问题，而是三个产品面没有隔离：

1. **医疗引擎中枢控制面**：知识、规则、路径、配置包、接入、运行、审计；
2. **SaaS 管理面**：租户开通、组织、人员、身份源、复杂数据范围；
3. **医院业务应用面**：患者、临床协同、随访、质量、医保。

首发目标实际是第 1 类，但默认导航、角色和门禁同时按三类产品设计，造成：

- 角色数量远高于当前团队人数；
- 低风险动作也需要不存在的组织角色接力；
- 模型与专家复核成为所有知识工作的心理和操作前置；
- 平台管理员既看到 SaaS 对象，又看到引擎对象，无法形成稳定心智模型；
- 用户为了完成演练被迫维护大量没有现实责任人的账号。

## 4. 采用方案

采用“兼容保留、默认收缩、按风险分流”的原位改造：

- 保留旧角色枚举、权限编码、API 和隐藏路由，避免破坏接口与历史审计；
- 只把 4 个职责设为客户默认可分配角色；
- 主导航只展示 5 个中枢域；
- 低、中风险候选统一归口知识运营员；高风险候选保留领域席位和双签；
- MFA 改为运行时配置，普通职责默认不要求；
- 模型增强从“全局上线门”改为“模型生产任务的能力门”；
- 用受控官方原件生成少量非诊疗 LOW 知识完成正式链路演练。

不采用以下方案：

- 不删除 501 处后端授权；
- 不把所有角色合并成一个万能管理员；
- 不让自动化冒充临床专家；
- 不把 MEDIUM/HIGH 医学建议降级成 LOW；
- 不为首发重写现有知识状态机；
- 不用数据库直写伪造正式知识或审核证据。

## 5. 上线角色模型

### 5.1 默认可分配职责

| 编码 | 首发显示名 | 核心责任 |
|---|---|---|
| `platform-governance-admin` | 平台管理员 | 中枢配置、账号、部署验收、运行总览 |
| `platform-knowledge-governor` | 知识运营员 | 来源、知识、术语、规则、路径、配置包、LOW/MEDIUM 审核发布 |
| `integration-operator` | 接入运维员 | 适配器、Provider、健康检查、国产化与故障恢复 |
| `compliance-auditor` | 审计查看员 | 只读审计、血缘、发布证据 |

`system-superadmin` 只作为内置应急账号，不允许客户手工分配。

### 5.2 兼容角色

其余既有角色编码继续可被历史 JWT、审计记录、隐藏页面和 API 测试识别，但：

- 不出现在账号角色选择器；
- 不由初始化和演练脚本创建；
- 不出现在默认角色旅程；
- 不作为 LOW/MEDIUM 首发知识流程的必需人员。

## 6. 上线信息架构

### 6.1 中枢概览

- 中枢工作台；
- 只展示可行动的阻断、待办、运行状态和最近证据。

### 6.2 医疗知识

- 来源与血缘；
- 术语与字典；
- 诊断知识；
- 规则配置；
- 路径配置；
- 配置包与发布；
- 知识关系。

### 6.3 生产与发布

- 知识审核与发布；
- 知识生产与发布。

“知识生产与发布”默认先展示受控来源初始化、候选和发布状态；模型 Provider、评测和模型任务作为“模型增强（可选）”区域，不再暗示无模型时系统不可运行。

### 6.4 接入与运行

- 账号管理；
- 系统接入；
- 运行保障；
- 安全与运行配置；
- 国产化核验；
- 实施与验收。

租户开通和身份来源不进入首发主导航；账号管理只允许选择 4 个首发职责，不展示复杂岗位角色。

### 6.5 审计证据

- 审计与证据。

患者索引、患者路径、提醒推荐、协同任务、随访、质量和医保页面保留为 `hidden` 或 `embedded`，不占据中枢控制面。

## 7. MFA 策略

新增配置：

```text
medkernel.auth.mfa.enabled=false
```

规则：

1. `system-superadmin` 始终要求 MFA，保持 CONSTITUTION 安全红线；
2. 其他首发职责仅在配置为 `true` 时要求 MFA；
3. 配置缺失、读取异常或非法值时，对普通职责按默认 `false`，但不得影响超级管理员强制策略；
4. 高风险配置守卫复用同一策略：普通职责在 MFA 关闭时不因未绑定被阻断，开启后恢复强制校验；
5. MFA 绑定、验证、恢复码和加密存储能力全部保留；
6. 关闭 MFA 不取消权限、确认语句、原因、乐观锁、审计、来源分离或高风险双签。

## 8. 知识审核与专家边界

### 8.1 LOW / MEDIUM

- `PLATFORM_SOURCE` 和首发 `TENANT_OVERLAY` 均归口 `platform-knowledge-governor`；
- 单个知识运营员可完成候选审核和激活；
- 来源登记人与来源批准人仍必须分离；
- 发布仍要求真实引用、来源版本、内容摘要、审计和统一版本状态机。

### 8.2 HIGH

- 继续建立归口席位和领域席位；
- 继续要求不同人员双签；
- 当前没有合格专家时保持待审或阻断，不自动降级、不自动签署；
- 高风险临床知识不属于本轮自动初始化范围。

## 9. 模型能力定位

模型能力调整为可选增强：

- 无 Provider、无模型 Key、无当前评测时，中枢、接入、B0、受控来源和 LOW 正式知识仍可运行；
- 创建 `API_MODEL` 正式生产任务时，才检查 Provider、当前制品评测、出域策略、版本三元组等模型门禁；
- 只有当前启用基准包含红线用例时才需要独立医学复核；
- P6 不再作为所有知识工作的全局门，只服务高风险或模型生产验收；
- 前端不得把“模型未配置”展示成“系统未上线”。

## 10. 正式权威知识初始化

清库部署演练自动建立 3 条以内 LOW 正式知识，边界如下：

- 来源为服务器上 SHA-256 已核验的 WHO 官方 PDF；
- 内容只包含文献身份、发布机构、版本、适用范围和精确来源锚点等非诊疗事实；
- 不包含治疗阈值、剂量、禁忌、自动决策、诊断结论或面向患者的建议；
- `generatedByModel=false`，不伪装成模型生成；
- 风险固定 `LOW`，并由清单校验器拒绝任何诊疗动作词或高风险字段；
- 来源登记账号与来源批准账号分离；
- 候选通过标准 API-03 和审核状态机激活；
- 演练验证 ACTIVE、引用、血缘、运行读取、审计和重复执行幂等。

该批知识用于证明正式知识主链可运行，不宣称临床指南内容已经完成专家审定。

## 11. 数据与兼容策略

- 不新增第二套角色表、权限表或知识状态机；
- 旧角色记录不物理删除，清库部署只播种首发角色；
- 旧菜单权限编码保留，隐藏页面不进入菜单目录；
- 不修改已执行迁移，新增配置优先走现有配置播种器；
- 正式清库仍使用现有带目标主机校验的部署脚本；
- 所有部署和初始化证据写入新的 release evidence 目录。

## 12. 验收标准

1. 4 个首发职责可创建、可登录、可进入各自主任务；
2. 普通职责默认不被 MFA 阻断，超级管理员仍强制 MFA；
3. 默认主导航只有 5 个中枢域，不展示 SaaS、临床和质量应用面；
4. LOW/MEDIUM 候选不再依赖不存在的临床、药事、医技或质量角色；
5. HIGH 候选仍无法单人激活；
6. 无模型时中枢健康、知识初始化、审核发布和读取链可用；
7. 3 条以内正式 LOW 权威知识在清库后真实激活且可追溯；
8. 前后端、CLI、MCP、五方言迁移、T-GATE 和浏览器关键路径全绿；
9. 134 清库、部署、初始化、重启、重复执行和回归演练都有脱敏证据；
10. 完成前只做本地提交；最终才推送分支、创建 PR、等待 CI、合并 `main`。
