## 0. 一页读懂（给实现者）

**这次重启不是新发明，是把一个已经规范完整、却被实现做爆、上不了线的系统，用狠的减法重写一遍。**

- 真实需求早就有：`FOUNDATION` 定了"先引擎全能力、后业务包装 + 十大引擎"；`业务场景 spec` 的 **S3 AI 知识工厂**主流程就是"探索→来源发现→存证→解析→新旧识别→候选→校验→审核→入包"；**S0–S40 已铺满全领域**（辅助诊疗/质控/随访/护理/医技报告/床旁/中医药…）。
- 病根是**被做成了 SaaS 平台 + 过度实现**：95 控制器 / 795 迁移 / 15 角色 / 九闸+双签+逐条审 / 五处看知识页 / 临床 SaaS 终端页 / 驾驶舱 / MFA·bootstrap 复杂登录 —— 把"规则引擎 + 赋能"这个精瘦核心埋了、中枢与引擎两头摇（"定位全乱"），复杂到无法正常上线。
- 重启动作：① S3 的"候选→人工逐条审"改成"候选→**全自动闸**→直接 ACTIVE"；② 人工只剩"上线时一个**旁路审批**，不卡管道"；③ 十大引擎**只借鉴逻辑、全新轻量重写**（不搬旧代码），全领域知识靠 S0–S40 覆盖矩阵当"内容"逐格灌，**绝不为每个场景另起引擎/页面/状态机**。

> **口径（贯穿全文 · 不可动摇）：项目全部重写——所有新方案与新代码全新、轻量化、零历史技术债。** 现有代码**与旧方案/旧文档都只读作借鉴参考**（学清楚需要的逻辑、安全边界、不变量、别再踩的坑），然后**全部用新代码、新方案干净轻量重写**——不复制文件、不沿用旧方案、不带旧依赖、不复刻旧分层/旧债。原样搬 = 把旧重量和技术债又拖回来，禁止。

**权威关系**：本文一经确认即为重构顶层目标，要求同步修订 [CONSTITUTION](../../CONSTITUTION.md) **§2/§6/§8/§15 + §0 内补核心澄清（定位不改）**（见 §13）。与旧卡/旧文档冲突，以"本文 + 修订后宪法"为准。

## 1. 产品定位

**MedKernel = 集团医疗智能中枢**（中文产品名；英文/代码名 `MedKernel`）。它的**核心/心脏 = 规则引擎 + 赋能**：用规则把医疗智能注入业务系统——一条自动管道从公域网 + 权威医疗网探索，生成覆盖**全领域**的整套医疗知识与规则，再以**规则引擎为核心的能力**经 **API + 页面嵌入 + 知识包**赋能业务系统（HIS/EMR/CDSS）。"引擎核心"是中枢的**内部能力核心**，不是对外产品名。

- **它不是 SaaS 平台**：不堆多角色管理控制台、不做临床终端页、不做驾驶舱产品。临床医生/护士/医技**不登录本系统**，在自己的 HIS/EMR 里被赋能；登录的只有引擎操作者（生产/审批/运营/审计）。
- 自动知识生成是**给规则引擎供料**；字典/路径/推荐/质控/随访/报告是**规则引擎赋能的延伸服务**，不是并列的一堆引擎/页面。
- 集团化 / 平台主权 / 多客户 / 内外网用**组织范围 + 环境维**承载，不堆角色。**管理控制台极小**（仅生产+治理）；但**演示台是核心功能、必须完整**——无真实患者也能完整演示全部能力（详见 §3 演示台），不可丢。

> **定位说明**：这就是原始宪法 §0 的口径（产品名=集团医疗智能中枢，引擎核心=内部能力名），**本重启不改定位**。膨胀期把它做成了 SaaS 平台、中枢/引擎两头摇——"定位全乱了"正是病根；重启是**恢复"中枢=产品、规则引擎=核心"的清晰**，不是重新定位。**宪法 §0 不改。** 临床安全边界（引擎不自动开医嘱、医师确认由消费业务系统承担）保留为 R8。

## 3. 系统结构（6 件 · 各管一件事）

| 件 | 干什么 | 对外接口 | 依赖 |
|---|---|---|---|
| **① 自动知识生产线** | 探索→抓取存证→解析锚定→新旧识别→候选→**自动闸**→ACTIVE，全程不停 | 提交领域格子 / 看流水线 | 领域覆盖矩阵、模型网关 |
| **② 知识库** | 知识资产信封；**平台主源 + 机构覆盖两层**；同域唯一 ACTIVE 原子替换 | 读写知识、查版本、解析有效版本 | 关系库（权威）+ 图（投影） |
| **③ 核心服务能力** | **以规则引擎为核心 + 赋能延伸**：规则拦截/查阅/字典/路径/推荐CDSS/质控/随访/报告/来源追溯/包分发 | API + 页面嵌入 + 知识包，统一输出契约，运行期纯辅助 | ② |
| **④ 上线旁路审批** | 知识照常自动 ACTIVE；发布包推真实上线时专家点批准 | 审批队列、`expertReviewed` 门 | 异步，**不阻塞 ①②③** |
| **⑤ 控制台 + 演示台** | 极小管理控制台(生产+治理) + **完整演示台**(同一套 API/嵌入演示验证全部能力，**核心功能不可丢**) | 4 入口：工作台·知识生产·引擎能力·系统治理 | ③ |
| **⑥ 极简底座** | 账户（密码+SSO）、少量角色、组织范围+环境、国产 DB/服务器、配置中心、审计 | 登录、租户、配置 | — |

**演示台（件⑤ 展开 · 核心功能，完整演示全部能力，不可丢）**

- 演示台**不是**独立引擎，是个 UI：选真实场景 → 调**同一套对外 API/嵌入**（沙盘抑制外部副作用，沿用 CURRENT/HISTORICAL_EXACT/COMPARE）→ 同屏亮起**规则拦截/查阅/字典/路径/推荐/质控/随访/报告**等全部能力结果，每条可点开看证据（来源/版本/hash/AI 标识）。
- **供 = 演**：演示台跑的就是引擎对外的真实 API/嵌入，**演示永远等于真实**；以 parity 断言保证演示路径与生产路径一致，不造数（R7）。
- **并排三视图**：原始 API 响应 ↔ 医生可读提醒 ↔ 嵌入组件实时预览（API 与嵌入两模式现场可见）。
- **场景库**：覆盖全部能力的真实场景（用药安全/急危重症/质控/字典映射…）+ 一张能力覆盖清单。散件（沙盘/各页"试一下"）收口进演示台、不重造。
- **这是中枢"无真实患者也能完整展示引擎能力"的核心功能，任何重启切片都不得丢**；每片新增能力必须同步进演示台（见执行计划 X5）。

## 4. 知识模型（唯一受治理实体 · 单一主版本 + 多层级机构覆盖）

全系统只有一种受治理实体：**知识资产**（信封：**身份 + 版本 + 来源 + 状态 + 适用域**）。术语/说明书/规则/路径/计算器/字典项/专病包…都是它的资产类型，共用同一信封。

**唯一核心 = 平台主版本（主源 `t-1`）**：所有知识都以平台主版本为**唯一权威基底**，由自动知识生产线产出。**机构绝不派生独立副本**（多层级机构各搞一套会知识爆炸、主版本失核心），只在主版本上叠**覆盖层（overlay）**——一份差量，不是整套复制。

**多层级机构覆盖**（集团 → 医院 → 院区 → 科室，各级都可设自己的覆盖层）：

- **运行时解析 = 就近覆盖叠加到主版本**：`科室 → 院区 → 医院 → 集团 → 平台主版本(基底兜底)`，就近的覆盖优先、逐级回落，**最终一定落到平台主版本**；某级无覆盖就用上一级/主版本。
- 机构覆盖只增量改写本组织范围、本机构生效；**不反写、不污染平台主版本，不作他方上游**（R5）；机构新增资产只归本机构。
- 同域唯一 ACTIVE（R4）= "主版本 + 生效覆盖叠加后的**有效版本唯一**"。
- 可复现：`来源 + 生产配置版本 → 同一内容 hash`（支撑 R2 + R10）。

**状态机（一套 · 生产全自动）**：
```
草稿 → 候选 →[自动质量闸]→ ACTIVE(可查阅/运行/演示) → 已下线 →(已归档)
                                  ╳ 推真实上线前：发布包级旁路审批放行
```
草稿/候选=知识生产；过自动闸→系统自动 ACTIVE；被新版原子替换→已下线（仅历史重放）。**无逐条人工审、无双签、无九闸。**

## 5. 自动知识生产线（全自动 · 一刻不停）

`探索 → 抓取存证 → 解析锚定 → 知识身份/新旧识别 → 候选(B0/模型) → 自动质量闸 → 入库 ACTIVE`

- **探索边界**：公域网自主获取只在**平台外网侧**（已审批白名单 / HTTPS / 许可 / robots / 拒私网 / 大小上限）；内网机构不爬外网，靠 §7 包分发拿平台主源。
- **B0 先于模型**（R6）：人工编著/权威来源结构化的 B0 即正式知识；模型做增量产候选，候选同样过自动闸；模型产出带 AI 标识（R1）。
- **自动质量闸（确定性 · 取代旧九闸/逐条审/双签）**：`schema 校验 + 红线结构完整 + 来源齐全可溯 + 重复检测 + 可复现 hash + 引用真实性`（引用真实性=机器校验候选引文确实出自所引来源对应位置，借现有医学回归/假引用判别逻辑，**不引人工**）。全过即自动 ACTIVE；**未过留在"候选"附失败原因、可修复重提，不自动 ACTIVE、不静默丢弃**（R7/R10）。
- **启用 Provider** = 纯技术就绪判定（健康检查 + 技术质量评测），全自动，不需要专家。

## 6. 上线旁路审批（唯一人工点 · 不卡运行）

- 生产、探索、生成、自动入 ACTIVE、演示台可用——**全程不等人**。
- 真实上线 = **院内部署** 或 **外网租户正式启用**（开始面向真实患者）。在此之前一律视为开发/演示/集成期，无需专家。
- 真实上线前：专家在审批队列对"该客户要上线的发布包"**点一次批准**，通过则发布包标 `expertReviewed=true` 方可 go-live。**审批挂在管道旁，不挡在管道中间**；专家没批，知识在平台里照样活着、可演示。
- 平台主源基础包 → 平台侧专家审；机构覆盖/启用 → 机构侧专家审；各自留痕。

## 7. 核心服务能力（规则引擎为核心 + 赋能延伸）

**规则引擎是核心**（把规则注入业务系统赋能）；其余是它的**赋能延伸服务**，不是并列引擎。全部借鉴现有逻辑、新写轻量代码（见 §11）。

| 能力 | 借鉴参考 | 输入 → 输出 |
|---|---|---|
| **规则拦截（核心）** | rule / cdss | 医嘱/事件 + 上下文 → 风险提醒（5 档）+ 依据 |
| 推荐/辅助诊疗 | recommendation / diagnosis | 症状体征检验 → 鉴别诊断候选 + 检查/治疗推荐 + 来源 |
| 知识查阅 | knowledge | 医学对象 → 权威说明 + 来源 + 标识 |
| 字典映射 | terminology | 院内写法 → 标准编码 + 置信（高危近似强制 HIGH，禁字符 LCS） |
| 专病路径 | pathway | 已确诊病种 + 状态 → 标准步骤 + 关键时点 |
| 病历质控 | evaluation / quality | 病历 → 缺陷清单 + 依据 + 整改 + 评分 |
| 随访 | followup | 出院/慢病患者 → 随访计划 + 到期提醒 |
| 报告解读 | recommendation / cdss | 检验/影像报告 → 异常项 + 意义 + 建议 |
| 来源追溯 | knowledge provenance | 一条知识/结论 → 出处链（类型/标题/版本/位置/hash/分级） |
| 包分发 | pkg | 一批已发布知识 + 目标 → 版本化包，发平台/客户、内/外网 |

**统一约束**：所有输出带 `status` + `source`（R2）+ `aiGenerated`（R1）。两种交付：**API**（业务系统自渲染）/ **页面嵌入**（iframe·Web 组件·SMART on FHIR·CDS Hooks 卡片，业务系统不重做界面）。

**运行期打扰梯度（R8 · 逐规则可配）**：

| 档 | 代码 | 行为 | 阻断 |
|---|---|---|---|
| L0 | SILENT | 静默旁路，只记录/角标 | 否 |
| L1 | INFO | 弹窗/卡片告知，可直接关 | 否 |
| L2 | ACK | 必须点"已知悉"才继续 | 否 |
| L3 | REASON | 填理由放行，理由留痕 | 软 |
| L4 | HARD_STOP | 硬停，业务系统按合同阻断该医嘱 | 硬 |

默认不打扰；到哪档由**规则配置**决定，引擎不统一强加；无强制双签。

## 8. 全领域覆盖（把原"中枢"全部能力范围收进引擎 · 当"内容"不当开发泳道）

"全领域" = **领域覆盖矩阵 × 同一条管道**：引擎按矩阵格子自动探索-生成直到覆盖，工作台看"已覆盖 X / 全 Y"。矩阵 = 原始需求里已规范好的全部范围，本轮**全部保留、只改谁是主体**：

- **资产类型**（原 §3.1 引擎资产总表）：来源 · 标准/院内字典 · 专病路径 · 规则 · 图谱(投影) · 推荐 · 评估 · 随访 · 护理专业 · 医技报告解读 · 床旁知识 · 中医药与综合照护 · 审计证据——都共用 §4 知识资产信封，不另起。
- **知识内容**（原 §3.2）：疾病 / 症状体征 / 检查检验 / 药品 / 器械耗材 / 手术操作 / 护理 / 医技报告 / 床旁 / 中医药 / 医保支付 / 公卫 / 院内制度，各按最小结构化字段产出。
- **专科路径必覆盖 10 阶段**（原 §3.3）：筛查分诊→初诊→风险评估→治疗决策→路径执行→监测预警→出院准备→康复随访→结局评估→闭环改进；缺项须显式标"不适用"，不无声缺失。
- **铺开顺序**（原 §3.4 P 批次）：P0 共用引擎闭环 → P1 高风险/连续照护 + 中国场景/协同 → P2 扩展与数据服务。

加新领域 = 往矩阵加格子，**复用同一管道 + 同一批引擎**，**封顶不开第二套引擎/页面/状态机**（防再次膨胀的硬约束）。业务服务包（试点/临床运行/质控/合规/第三方/专病/专业协同）= 引擎能力的**组合包装**，不另起实现；本轮重启**先把引擎主干 + 自动生产线跑通**，业务包装后置。

## 9. 角色与登录（极简 · 引擎操作者，非临床 SaaS）

- **登录**：账户密码 + **SSO 单点登录**。删 MFA 强制、bootstrap token 等复杂流（超级管理员仍独立高亮审计）。
- **只有引擎操作者登录**；临床医生/护士/医技**不登录本系统**，在自己的 HIS/EMR 里经 API/嵌入被赋能。
- **角色 = 权限预设包 × 范围（平台主源 t-1 / 机构）× 环境（内/外网）**，5 预设：

| 预设 | 职责 | 范围 |
|---|---|---|
| 超级管理员 | 系统兜底，强制内置、不可降权/旁路、独立审计 | 仅平台 |
| 知识工程师 | 跑探索、跑生产、编著规则与知识候选（全自动入库，无需人工逐条审） | 平台 或 机构 |
| 医学专家 | **仅真实上线前**做一次旁路审批（R9） | 平台 或 机构 |
| 运维工程师 | 接入/Provider/配置/部署/运行保障/国产化 | 平台 或 机构 |
| 审计员 | 只读查审计与证据 | 平台 或 机构 |

- **机构自管（必须）**：机构侧也有知识工程师/医学专家/运维工程师/审计员（超级管理员仅平台），登录后自管**本机构覆盖（定制）**与**本机构上线审批**；职责分离（知识工程师≠医学专家），不反写平台主源（R5）。
- 被移除的旧 15 临床/治理登录角色 → 改为业务系统经 API/嵌入消费。
