# 医学回归独立专家复核设计

## 目标

让质量治理员能够在产品界面内查看候选模型医学回归运行的逐用例真实证据，并在满足职责分离、MFA、证据完整性和当前基准一致性后完成专家复核签字。任何缺证据、旧基准、失败用例或越红线运行都不得放行。

## 归属与边界

- 页面独立归属“质量管理”，路径为 `/qc/model-evaluations`，不混入“评价指标”，也不把质量治理员带入模型配置或知识生产页面。
- 页面只提供运行查询、证据核查和待复核运行签字；不提供 provider 配置、密钥、提示词正文、执行评测或基准集维护。
- 复核签字继续要求 `llm.eval.manage`、`quality-governor`、已绑定 MFA、签字人与执行人分离。
- 普通字段使用医院语言；运行 ID、provider code、能力码和原始引用载荷只在全局专家模式显示。

## 数据与接口

- V151 新增 `mk_llm_eval_case_evidence`，按运行保存用例快照、模型输出、来源引用、期望命中、引用核验、红线判定、通过标记和失败原因；新增运行复核意见字段与质量域菜单权限。
- `GET /api/v1/model-evaluations/runs` 按当前租户、状态和服务端分页返回安全摘要。
- `GET /api/v1/model-evaluations/runs/{runId}` 返回运行摘要和逐例证据，不返回租户字段或凭据。
- `POST /api/v1/model-evaluations/{runId}/sign-off` 要求显式证据确认和非空复核意见。
- 运行评测与逐例证据在同一事务持久化；任何证据写入失败时整次运行回滚。

## 签字门禁

签字前必须同时满足：运行属于当前租户且状态为 `PENDING_REVIEW`；逐例证据条数等于运行总用例数；全部证据通过且无假引用、红线突破；当前启用基准集与运行指纹一致；签字人不是执行人；MFA 高风险校验通过；请求已确认逐例证据并填写复核意见。状态更新使用条件更新，阻断并发覆盖。

## 产品状态

页面覆盖加载、空、错误、无权、就绪和提交中状态；默认筛选待复核，列表服务端分页。详情抽屉逐例展示证据，签字弹窗只保留一个主按钮，失败使用医院语言并保留追踪号。
