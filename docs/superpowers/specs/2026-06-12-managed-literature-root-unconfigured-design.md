# 平台知识文献资料库未配置态设计

> 日期：2026-06-12  
> 状态：已按“正式知识生产前全新处理、不留历史包袱”口径批准执行。

## 1. 问题

配置中心键 `medkernel.knowledge.literature.material-root-uri` 当前以 COS URI 作为代码种子。该做法虽然可运行，但把正式基础设施选择写进产品代码，与“正式地址只能通过系统配置页维护、不得绑定服务器 IP 或存储厂商”冲突。

## 2. 方案比较

1. 保留 COS 默认值：开箱可见，但把厂商和桶名固化进代码，不采用。
2. 写死中立 HTTPS 网关：表面中立，实际仍伪造并绑定未部署基础设施，不采用。
3. 以空值表示“未配置”：配置项和治理元数据仍由平台种子创建，页面明确显示未配置；管理员必须通过系统配置页写入合法受管 URI，采用。

## 3. 设计

- 配置项继续在启动期写入关系库，`source=PLATFORM_SEED`、高风险、受保护、版本为 1，但初始值为空。
- 系统配置页对空值显示“未配置”，并以警告态提示正式知识生产前必须完成配置。
- 编辑入口继续接受 COS、S3、OSS、OBS、MinIO 和 HTTPS 网关等带 URI scheme 的受管地址；拒绝 `file`、`tmp`、`local`、`classpath`、非加密 HTTP、缺少固定资料目录结构或末尾斜杠的值。
- 运行读取在缺值或空值时返回空字符串，不回退到本机目录、临时目录或任何厂商地址。
- 正式知识生产阶段必须把“值非空且通过受管 URI 校验”作为放行条件；本次不扩展知识生成模块。

## 4. 验收

- 后端测试证明空库启动后配置项存在、值为空、来源为 `PLATFORM_SEED`。
- 后端测试证明非法本地 URI 被拒绝，合法 S3 URI 可经高风险配置更新保存。
- 前端测试证明空值显示“未配置”，编辑保存仍走系统配置 API。
- 远端空白 PostgreSQL 库从 V1 迁至 V116 后，配置项以未配置态存在，服务 readiness 为 200。
