> 状态：设计稿（已评审深化，待提交）｜日期：2026-06-03

> 关联场景：详规 [S16 辅助诊疗与鉴别诊断](../../MEDKERNEL_BUSINESS_SCENARIO_DETAIL_SPEC.md)（含 S17 检查推荐、S18 用药安全）

## 1. 背景与要解决的问题

辅助诊疗/鉴别诊断（S16）当前**无处落地**：

- 推荐引擎 `engine/recommendation` 只做"卡片生命周期治理"，候选卡靠外部传入，**不会自己产出鉴别诊断**。
- 鉴别诊断的"依据"（候选疾病、支持/反对证据、鉴别清单）当前**没有承载结构**——规则引擎是确定性 IF-THEN 质控工具，装不下"按证据强度排序的疾病候选"；知识引擎只存证据文档，没有结构化的"诊断标准"。
- 首发知识资产（KNOWGEN-06）推荐模板只覆盖"用药/检查/治疗/路径下一步"，**不含诊断模板**。

### 关键认知（破除"路径爆炸"误解）

诊断、治疗、路径是**三层解耦**，不是"一个诊断配一条路径"：

| 层 | 职责 | 数量级 | 承载 |
|---|---|---|---|
| ① 诊断假设（鉴别诊断） | 发现 → 候选疾病 + 支持/反对证据 | 知识条目 | **诊断知识资产（本设计新建）** |
| ② 治疗推荐 | 诊断 → 用药/检查/处置候选 | 细粒度、可复用 | 规则 + 知识检索（已有） |
| ③ 路径 | 确诊后跨多日多科室的标准化协同 | **仅几十个专病** | 路径引擎 PATH-01（已有） |

绝大多数诊断只走到 ②，**不进 ③**。路径数量 = 专病数（几十~一两百），不随诊断数（几万）爆炸。本设计补的是 ① 这层缺口，并定义 ①→②→③ 的衔接。

## 2. 设计原则与约束（不可违背）

1. **不自动诊断**：输出"疾病候选 + 证据"，必须医师确认；规避 NMPA 三类辅助决策医疗器械边界（OPT-03）。
2. **置信用分级、不用百分比概率**：输出"强支持/中等支持/弱支持/建议排除"等级，**不输出伪精确概率**——百分比概率等于"计算诊断结论"，触三类器械红线；分级 + 证据列表是合规的"辅助呈现"。
3. **无候选 ≠ 排除疾病（医疗安全红线）**：无候选/证据不足时返回**诚实空态**"系统无意见"，**绝不可被读成"已排除/没事"**。卡面文案、接口语义、空态都必须显式声明这是"系统无足够依据给出提示"，不是阴性诊断结论。
4. **B0 先于模型**：诊断知识命中是确定性的，不依赖模型；模型只作可选增强挂点，关闭返回 `MODEL_DISABLED`、不降可用性。
5. **AI 标识可追溯**：诊断知识若由 AI 生成草案，资产与卡面必须标 AI 来源（复用 `RecommendationCard.aiGenerated`）；运行时若用模型增强，输出标 AI 参与且可降级。
6. **关系库权威**：诊断知识落关系库；图/搜索是投影，可关可重建。
7. **复用现有引擎**：最大复用 KNOW-01（身份/版本/来源/可信分级/发布/投影/继承）、RULE-01（红线 + DSL 算子）、PATH-01（路径衔接）、CDSS-01（推荐卡治理）；不新立大域。
8. **发现项引用标准术语编码**：诊断标准里的"发现"全部引用 TERM-01 标准术语编码，不写死中文——保证患者数据、诊断知识、规则三方用同一套编码可对齐，并避免知识层重复膨胀。
9. **不写死医学常量**：置信分级的"权重→等级"映射、阈值，必须可配置/可审计/可按科室覆盖，不得硬编码在代码里（守 §8 + T-GATE）。

## 3. 全链架构

```
患者标准上下文(API-01 快照：发现编码集合，经 TERM-01 标准化)
   │
   ▼
① 诊断假设命中(确定性 B0)
   │  匹配 ACTIVE 诊断知识版本的诊断标准(支持/反对/必需/排除 + 时序约束)
   │  → 候选疾病(并列竞争) + 支持/反对证据 + 缺失必需项 + 置信分级
   │
   ├──并行──▶ 规则引擎 OPT-04 红线(危急值/DDI/致命不可漏) ──强优先、不可抑制
   │
   ▼
CDSS-01 合流 + 排序(高危先行 > 证据充分 > 来源可信)
   │  组装 RecommendationCard(cardType=DIAGNOSIS_ASSIST)，复用 trigger 落库/反馈/疲劳/审计
   │  每卡挂命中的诊断知识 ID+版本，可回链 criterion→citation→source
   ▼
辅助诊疗卡(标"辅助建议，需医生确认"；空态标"系统无足够依据") ──▶ 医生采纳某诊断
                                                                      │
                                                                      ▼
                                                ② 治疗推荐(规则+知识) → 用药/检查候选
                                                                      │ 若属专病 且 满足入径
                                                                      ▼
                                                ③ 软建议转入 PATH-01 专病路径(医生确认)
```

## 4. 详细设计

### 4.1 诊断知识资产（① 层的家）

**复用知识引擎地基，新增 domain 与结构化 payload。**

- **诊断身份**：复用 `KnowledgeIdentity`，`KnowledgeDomain` 新增枚举值 `DIAGNOSIS`。承载标准诊断名 + ICD 编码 + 同义/本地名 + 适用专科/组织范围；一疾病一身份，版本化、七层组织继承、平台主源回退（复用现有机制）。
- **诊断版本**：复用 `KnowledgeAssetVersion`（可信分级 A–E、发布状态机、`content_hash`、生效域唯一约束）。
- **版本内结构化 payload（新增子表）**：

| 子表 | 装什么 | 关键字段 |
|---|---|---|
| `mk_diagnosis_criterion` 诊断标准 | 支持/反对该诊断的发现 | `finding_term_code`(引用 TERM-01 标准术语) · `direction`(SUPPORTING/REFUTING/REQUIRED/EXCLUSION) · `weight`(MAJOR/MINOR) · `value_constraint`(可选，复用规则 DSL：between/unit_compare) · **`temporal_constraint`**(可选时效/趋势，复用 DSL temporal：如"48h 内""动态升高") · `citation_id`(来源锚点) |
| `mk_diagnosis_differential` 鉴别清单 | 要与谁鉴别、怎么区分 | `differential_identity_id`(指针到另一诊断身份) · `key_point` · `suggested_workup`(建议补充检查编码) · `bidirectional`(是否运行时反向解析，默认 true，避免两边重复维护) |
| `mk_diagnosis_care_pointer` 诊疗指针 | 确诊后去哪 | `pointer_type`(TREATMENT/WORKUP/PATHWAY) · `target_ref`(指针到规则/知识/PATH-01 模板) · `is_soft`(路径恒为软建议) |
| `mk_diagnosis_test_case` 诊断测试病例 | 发布门禁的回归集 | `findings`(发现集) · `expected_identity_id`(期望候选) · `expected_confidence`(期望分级)；发布前必须全绿（见 4.6） |

- **时序维度（补充点 1）**：`temporal_constraint` 让 criterion 表达"3 天内的发热""肌钙蛋白动态升高"等病程语义，复用 RuleDslEvaluator 的 temporal 算子，不另造时间引擎。
- **防知识层爆炸（补充点 4）**：发现项统一引用 TERM-01 编码（不写死文字），`mk_diagnosis_criterion` 对 `finding_term_code` 建索引，支持"发现→疾病"反向查询；维护落在"发现"和"疾病"两个可控维度，而非其笛卡尔积；鉴别关系单向声明、运行时双向解析。
- 每条标准/鉴别挂 `citation_id`，复用 KNOW-01 的 `Citation`→`SourceFragment`→`SourceDocument`，满足 S16 验收"来源可追溯"。
- 迁移：V67 五方言（h2/postgres/oracle/dm/kingbase），表名 `mk_diagnosis_*` owner 前缀，中文 `COMMENT ON`，含组织/版本/审计字段与索引约束。
- owner：诊断知识结构归 `engine-knowledge`（DomainOwnershipCatalog 登记诊断子族）。

### 4.2 置信分级（语义 + 可配置映射）

确定性、可复现、**无百分比**。等级语义（默认，可配置覆盖）：

| 等级 | 默认判定 |
|---|---|
| 强支持 | 满足全部 REQUIRED 且命中 ≥N 项 MAJOR，无 EXCLUSION |
| 中等支持 | 满足 REQUIRED 且命中部分 MAJOR/MINOR |
| 弱支持 | 仅命中 MINOR 或 REQUIRED 部分缺失 |
| 建议排除 | 命中 EXCLUSION 或关键 REQUIRED 明确为阴性 |

**映射可配置（补充点 2）**：上述阈值（N、权重组合、是否计入时序）放 `mk_diagnosis_confidence_policy`（按租户/科室可覆盖、可审计、版本化），**不硬编码**。守 §8"不写死医学常量"与 T-GATE。

### 4.3 运行时合流（鉴别诊断流程）

`RecommendationEngineService` 新增确定性诊断命中编排（owner：`engine-recommendation`）：

1. **取患者发现**：从 API-01 上下文快照取发现编码集合（症状/体征/检验/检查/既往诊断/用药），含时间戳。
2. **标准化前置与部分可用（补充点配套）**：发现须经 TERM-01 标准化；未标准化项不阻断整体——可用项照常命中，未标准化项计入响应"未纳入清单"（计入响应 `unmappedFindings`，正常响应字段、不设错误码），对应六态"部分成功"，不猜不补。
3. **候选生成（竞争假设并列）**：匹配当前适用域 ACTIVE 诊断知识版本的 `criterion`——SUPPORTING/REQUIRED 命中→进候选；EXCLUSION→标"建议排除"；REFUTING→降权。**多个候选并列竞争，不自动排他**（排他=下结论）。
4. **证据装配（含矛盾）**：每候选列 支持证据 + 反对证据 + **缺失的 REQUIRED**（"缺什么证据"）；同一发现同时支持 A、反对 B 时，在两卡上**显式呈现矛盾**，交医师判断。
5. **置信分级**：按 4.2 可配置策略映射到等级，可复现、无百分比。
6. **红线合流**：并行调规则引擎 OPT-04 红线（见 4.4）；命中→强制高优先 + `requiresPhysicianConfirmation=true` + 不可疲劳抑制。
7. **排序**：高危先行（红线）> 证据充分（命中权重）> 来源可信（知识 A–E 分级）——即 S16 规定顺序。
8. **组装与统一治理**：复用 `RecommendationCard`，`cardType=DIAGNOSIS_ASSIST`；引擎生成候选后**走与 trigger 相同的落库/反馈/疲劳/审计路径**（统一治理，不另起一套）；每卡挂命中诊断知识 `identityId + versionId` 与 `criterion`→`citation` 解释链。
9. **空态安全**：无候选时返回诚实空态，文案"系统无足够依据给出提示，非排除诊断"（原则 3）。

全程不写诊断、不下医嘱；卡面恒含"辅助建议，需医生确认"。

### 4.4 红线合流与边界判定原则

方案 C 两路的**划分标准**（避免实现期模糊）：

- **走规则引擎 OPT-04 红线**：致命不可漏、时间敏感、确定性可判的——危急值、严重 DDI、高危禁忌、必须排除的致命病（如主动脉夹层之于胸痛）。特征：确定性、强优先、**不可被疲劳抑制**。
- **留诊断知识**：概率性、支持/反对性的常规鉴别证据。特征：分级呈现、可被疲劳治理。
- 二者在 CDSS 合流：红线决定"必须置顶且不可压制"，诊断知识决定"候选与证据"。

### 4.5 诊断 → 治疗 → 路径衔接

- **②治疗**：`care_pointer(TREATMENT/WORKUP)` 指向规则/知识；医师采纳诊断后复用 S17/S18 规则+知识检索产出候选（结构化映射深化留 Spec 2）。
- **③路径**：`care_pointer(PATHWAY)` 指向 PATH-01 专病模板，**恒为软建议**（`is_soft=true`）；实际入径仍由 PATH-01 入径条件门禁 + 医师确认，诊断知识**不硬绑路径**，避免耦合与"路径爆炸"。

### 4.6 诊断知识测试病例与发布门禁

类比 RULE-01 测试病例全绿 / KNOWGEN-04"每条带测试病例"：

- 每个诊断知识版本带 `mk_diagnosis_test_case`（发现集→期望候选/置信）。
- **发布前必须全绿**：测试病例跑出的候选/分级与期望一致，否则不得 ACTIVE。
- 与 OPT-06 AI 质量评测中心协同（回归集、幻觉拦截）。保证"命中可复现、无假命中"（T-GATE 真实性）。

### 4.7 降级（B0）与 AI 标识

- 诊断知识命中即 B0 确定性，无模型可跑；模型增强（语义扩展发现、自然语言解释）为可选挂点，关闭返回 `MODEL_DISABLED`。
- 无图投影、无 Dify 不影响（图仅可视化）。
- AI 标识：AI 生成的诊断知识草案标 `aiGenerated`，必经人工审核发布才生效；运行时模型参与的输出标 AI 且可降级。

### 4.8 安全、审计、可观测

- 安全：不自动写诊断/医嘱；红线候选强优先不可抑制；空态非阴性结论（原则 3）。
- 审计：命中/采纳/不采纳留审计（复用 `IsolatedAuditPublisher`，失败也留痕）。
- 可观测（OBS-01）：命中链路 trace、同输入+同版本可复现；新增业务指标（类比 `incCdssAlerts`）——diagnosis-assist 调用数、候选分级分布、采纳率。

### 4.9 性能与索引（NFR）

- S16：候选生成 P95 ≤1s、10 万患者级。
- 索引：`mk_diagnosis_criterion(finding_term_code, tenant, 适用域)` 反向索引，按患者发现编码集合批量命中 ACTIVE 版本；避免逐疾病全扫。
- 服务端分页、并发幂等（同上下文+版本可复现）。

### 4.10 多租户继承

复用知识引擎七层组织继承 + 本租户覆盖优先、回退平台主源 `t-1`；置信策略（4.2）按科室覆盖。

### 4.11 API 契约

- **运行（鉴别诊断）**：`POST /api/v1/engine/recommendations/diagnosis-assist`，入参 `contextSnapshotId`（或患者/就诊 + 发现集合）+ 12 字段统一上下文；出参疾病候选列表（候选疾病/支持证据/反对证据/缺失必需/置信级别/鉴别清单/建议检查/来源/风险提示/未标准化未纳入项）。归推荐引擎下、复用推荐卡治理，**不新立"诊断"独立接口**（守监管措辞 + 对齐详规"复用推荐卡"）。
- **维护（诊断知识）**：复用/扩展 `/api/v1/engine/knowledge/**`，诊断知识 CRUD/审核/发布/灰度/回滚走知识引擎现有流。
- 复用既有：推荐卡列表/详情/来源/反馈/疲劳/诊断（`/engine/recommendations/**`）。

### 4.12 错误码

复用 `ENG_REC_*`、`ENG_CONTEXT_001`（snapshot 不存在，由 `ContextSnapshotService.findById` 抛）；新增诊断族（真实签名 `(code, httpStatus, message, ErrorClass.DATA, false)`）：`ENG_DX_001` 诊断知识版本无效/未发布 · `ENG_DX_004` 鉴别引用身份不存在 · `ENG_DX_005` 置信策略缺失/非法 · `ENG_DX_006` 测试病例未通过、不得发布（发布门禁）。**未标准化发现进响应 `unmappedFindings`、无候选返回空 `candidates` + `advisoryNote`——均为正常 200 响应，不设错误码（原 `ENG_DX_002/003` 取消，避免定义不用的死码）。**

## 5. 单元边界（可独立理解/测试）

| 单元 | 职责 | 依赖 | 可测点 |
|---|---|---|---|
| 诊断知识资产（结构+仓储） | 存身份/标准/鉴别/指针/测试病例 | KNOW-01 身份/版本/来源 | 增删改查、来源锚点、时序约束、版本发布、测试病例门禁 |

## 7. 分阶段实现

全链愿景一次设计、分期落地：

- **Spec 1（本设计聚焦 / MVP）**：诊断知识资产（结构含时序/测试病例 + 维护 + 发布门禁）+ 可配置置信策略 + 运行时确定性鉴别诊断卡（候选/证据/缺失/矛盾/分级/来源 + 部分可用 + 空态安全）+ 红线合流 + AI 标识 + 可观测。端到端产出一张真实可解释的鉴别诊断卡。
- **Spec 2**：② 诊断-治疗映射结构化深化（用药/检查候选，接 S17/S18）。
- **Spec 3**：③ 诊断→路径软衔接落地 + AI 工厂（AIK-STD-04/Dify）诊断知识草案生成→人工审核发布 + OPT-06 评测中心深度集成。

## 8. 验收映射

- S16：任意候选可解释"为什么推荐/缺什么证据/来源/适用范围" → 4.3 步骤 4/8 满足；P95 ≤1s → 4.9。
- CDSS-01 AC-1/2/3：命中可追溯版本、反馈回写疲劳、红线强优先不被抑制、关模型 B0 仍跑 → 4.3/4.4/4.7。
- 监管：不自动诊断、置信分级非概率、无候选非排除、医师确认、AI 标识 → 第 2 节原则 1/2/3/5 + 4.7/4.8。
- 真实性 T-GATE：测试病例全绿、置信映射不硬编码、命中可复现 → 4.2/4.6。

## 9. 风险与未决

1. 置信映射默认阈值需临床校准：首发给保守默认 + 科室可配（4.2），不写死。
2. 发现项依赖 TERM-01 标准化覆盖度；未标准化项进响应 `unmappedFindings` 部分可用、不猜（4.3 步骤 2，正常响应字段、非错误码）。
3. 首发诊断知识"料"来源：Spec 1 用少量高频专病人工种子验证链路（带测试病例），规模化生成留 Spec 3（AI 工厂）。
4. 竞争假设的呈现密度需配合 REMIND-01 低打扰：候选数量上限/折叠策略，实现期定，默认保守。
