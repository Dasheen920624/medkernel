# 术语表（医院听得懂的话 vs 技术名词）

> 定位：核心 §术语指针指向本表。客户面菜单/按钮/列名严禁出现技术缩写（除非已是医院术语，如 DRG/MPI/ICD）。
> 来源：迁自宪法 §7 术语表 + 详规术语条目；不自创同义词。

| 客户面（推荐） | 不要这么说 | 含义 |
|---|---|---|
| 集团医疗智能中枢 | 引擎中心 / 中台 | 中文产品名（英文/代码名 = MedKernel）|
| 试点准备 | 系统初始化 / 实施配置 | 医生用之前实施 + 信息科要做的全部配置 |
| 临床运行 | 临床嵌入器 / 临床应用层 | 医生日常用的提醒、待办、路径执行 |
| 质控改进 | 数据中台 / 分析平台 | 院长 / 医务处 / 质控办看效果 |
| 合规运维 | DevSecOps / SRE | 信息科主任 + 合规审计的工具 |
| 配置包 | Asset Bundle / 资产包 | 把已发布的字典、知识、规则、路径等资产按版本和适用范围打成一个可校验、可发布、可离线导出的包 |
| 标准术语 | StandardTerm / 标准字典行 | ICD-10、LOINC、ATC 等行业或平台认可的标准编码和名称，是院内代码对照的目标 |
| 院内术语 | LocalTerm / 本地字典行 | HIS、LIS、药房等院内系统里的原始代码和名称，如 `K001 血钾` |
| 字典映射 | Terminology Mapping / 码表关系 | 把一个院内术语确认到一个标准术语的关系；确认后才能进入术语映射包 |
| 高危近似候选 | High-risk Candidate / 负样本 | 看起来相近但临床后果不同的候选，如钾/钠；必须逐条二次确认，禁止批量确认 |
| 映射冲突 | Mapping Conflict / 一对多/多对一 | 一个院内码命中多个标准码，或多个院内码指向同一标准码时的人工裁决事项 |
| 术语映射包 | Terminology Package / 字典包 | 已确认映射冻结出的配置包草稿；只有经发布适配器同步并发布后，才成为运行态有效快照 |
| 临床路径 | Pathway / Pathway Template | 针对一个病种的标准诊疗流程，从入院评估、治疗、复评、分支处置到出院评估都有节点、时间窗和责任记录 |
| 路径节点 | Pathway Node | 临床路径里的一个可执行或可评估步骤，如 CURB-65 入院评估、48-72h 疗效评估、出院评估 |
| 里程碑 | Milestone | 路径中必须在目标时间内完成的关键节点或阶段，如 24h 内完成入院评估 |
| 变异 | Variance | 患者实际执行偏离标准路径的情况，需要记录原因、责任人和后续处置，如抗菌治疗升级 |
| 降阶梯 | De-escalation | 疗效改善或培养结果支持后，从广谱或强治疗逐步收窄到更合适治疗方案的临床动作 |
| 知识来源 | Knowledge Source / SourceDocument | 指南、法规、院内制度、文献或本地制度目录等原始依据；登记后才能拆锚点、生成知识版本引用 |
| 来源锚点 | Source Fragment / Anchor | 知识来源中的可精确追溯片段，记录锚点路径、片段指纹、引用关系和证据权重 |
| 知识身份 | Knowledge Identity | 一条稳定的知识主题，如“血钾危急值阈值与报告时限”；身份不等于版本，历史版本可替换但身份保持可追溯 |
| 知识版本 | Knowledge Version | 某个知识身份在特定来源、范围和发布时间下的可发布版本；只有发布后才能成为当前权威版本 |
| 知识会签 | Review / Sign-off | 医务处、专家或授权质控员对知识候选进行审核并留下签名证据；高风险版本必须会签后发布 |
| 知识替代 | Supersession / Replacement | 新版本接替旧版本成为当前权威版本；旧版本保留历史追溯，但不再作为默认有效版本 |
| 临床决策支持 | CDS / CDSS | 根据患者上下文、规则、路径和知识来源给医生提供提醒或建议；只能辅助决策，不能自动开医嘱或替代医生确认 |
| 推荐卡 | Alert Card / Recommendation Card | 医生端看到的一条提醒或建议，必须带风险级别、来源、解释、建议动作和反馈入口 |
| 提醒治理 / 疲劳治理 | CDSS Fatigue Management | 治理"医生收到太多无用提醒"的问题，包括命中统计、反馈分析、抑制信号和待改规则 |
| 覆盖 | Override | 医生有临床理由不采纳推荐卡时记录的人工覆盖，必须填写原因并留审计，不能等同于系统自动放行 |
| 影子模式 | Shadow Mode | 规则在后台记录命中和反馈，但不向医生端生成动作卡，也不改变诊疗流程 |
| 灰度发布 | Canary Deploy | 先只发给一个科室、院区或指定人群验证，边界外组织不得被影响，验证后才允许全量 |
| 撤回 | Withdrawal / Safety Recall | 已发布资产或配置包因安全、质量或来源问题被主动拉回；撤回后继续发布必须被阻断并留下影响摘要 |
| 离线导出 | Offline Export | 把配置包及其 manifest、摘要和资产快照导出给封闭网络或离线院区导入前校验，不等同于直接生效 |
| 对账 | Reconciliation | 导入或同步前比对版本、摘要、条目数量和目标侧已有资产；发现重复或冲突时停下来人工确认 |
| 闭环 | Closed Loop | 从提醒、确认、处理到复核完成都有时间、责任人和结果记录，不能只停在“已提醒” |
| 随访计划 | Follow-up Plan | 患者出院或阶段治疗后生成的后续管理安排，包含电话随访、问卷、门诊复评或再入院观察等任务 |
| 指标 | Quality Indicator / Measure | 质控办定义的可计算评估口径，如危急值 30 分钟闭环率或抗菌药物 48-72h 疗效评估完成率 |
| 预警 | Quality Alert | 质控问题达到阈值或存在高风险未闭环时生成的提醒，必须能追溯到问题、科室和证据摘要 |
| 整改 | Rectification | 责任科室针对质控问题提交原因、处置和证据，并由质控办复核关闭或退回的闭环动作 |
| 医疗安全红线 | Safety Red Line | 绝不能被演示便利绕过的底线，如禁止自动开嘱、高危需双签、AI 结论必须标识并由医生确认 |
| 配置包中心 | Asset Registry | 配置包的管理与发布 |
| 平台主租户（唯一内置） | 默认租户 / 集团总院 / 历史误生成租户名 | 唯一内置平台数据租户，ID 为 `t-1`；全局医疗知识和标准包默认在这里生成，客户集团 / 医院租户从这里分配或派生 |
| 平台源订阅 / 快照 | 客户主源 / 二级主源 / 平台源副本 | 从平台主租户授权给客户 / 集团租户读取的只读发布版本、订阅引用或离线快照；不得物理同步成客户主源资产行，客户定制必须生成本租户覆盖 |
| 客户租户 | 平台租户 / 默认租户 | 客户集团、医院、院区等业务租户；默认读取平台主源，允许在本租户内定制覆盖和新增，但不得回写污染平台主租户的知识源 |
| 租户 | 数据库实例 / 项目空间 / 环境 | 一家客户或一个客户集团在系统里的独立业务边界；账号、组织、规则覆盖、审计和发布状态均按租户隔离 |
| 组织范围 | Scope / 数据域 / 权限范围 | 角色能作用到的医院、院区、科室或租户整体；例如医生只管本科室，审计员可看当前租户审计 |
| 五维权限 | RBAC / ACL / 权限点 | 同时看角色、动作、组织范围、环境、菜单五件事；页面能不能看、按钮能不能点、数据能不能查都不能只靠角色名判断 |
| 角色 | Role / 岗位编码 / 用户组 | 医院岗位在系统里的权限原型，如临床医生、护理人员、医技技师、临床药师；新岗位先映射既有角色，不随意新增角色 |
| 适配器中心 | Adapter Hub | HIS / EMR / LIS / PACS 等接入点的管理 |
| 驾驶舱 / 院级驾驶舱 | Executive Dashboard | 院长、医务处和质控办看的全院或科室总览，必须可下钻到质控问题、预警、整改和证据 |
| 来源追溯 | Provenance | 任何提醒可追溯到指南、文献、知识库哪一条 |
| 国密 | SM2 / SM3 / SM4 | 国家商用密码标准算法 |
| 国产化自检 | Domestication Check | 检查当前 OS/JDK/DB/中间件的国产化程度 |
| MPI | Master Patient Index | 患者主索引 |
| DRG / DIP | Diagnosis Related Groups / Diagnosis Intervention Packet | 医保付费分组 |
| 系统配置中心 | Config Center / 配置管理后台 | 功能开关、认证策略、备份、国产化、Provider、安全基线、日志级别的前台统一管理（挂"安全基线与系统配置"二级菜单）|
| 接管码 | Init Token / Bootstrap Token | 首次部署时由值班运维生成的一次性校验码，用来证明当前操作者有权把裸系统接管成可登录系统；只走受限部署通道，不进仓库或聊天记录 |
| 双因素认证 | MFA / TOTP | 登录密码之外的第二道身份确认，首次接管后必须绑定；高危配置和租户开通前必须能证明操作者身份 |
| 恢复码 | Recovery Code | MFA 设备丢失时的一次性恢复凭据，只展示一次；系统只保存摘要，工单和证据不得记录明文 |
| 就绪态 | Readiness | 验收自检项的真实状态，分为就绪、阻塞、未启用；阻塞表示上线前置条件未满足，未启用表示当前阶段或开关未打开 |

> 客户面菜单 / 按钮 / 列名严禁技术缩写。新增术语按本表三列粒度补入，不另起同义词。
