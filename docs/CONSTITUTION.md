## §0 产品定位与命名

> MedKernel = **集团医疗智能中枢**：把指南、路径、规则和院内数据接起来，在临床现场提醒医生，在质控侧形成整改闭环，并留下合规证据。

| 类型 | 标准名称 | 使用范围 |
|---|---|---|
| 中文产品名 | **集团医疗智能中枢** | 对外介绍、页面标题、登录页、文档标题、客户汇报 |

## §2 菜单 IA（三产品空间 · 全功能保留）

MedKernel 使用医疗引擎、知识生产、平台管理三个产品空间。空间只做任务分区，不裁剪页面：

| 产品空间 | 业务域 | 主要职责 |
|---|---|---|
| 医疗引擎 | 工作台、知识治理、临床协同、质量管理 | 医疗引擎运营员、临床使用者 |
| 知识生产 | 来源、解析、模型生成、安全门、影子、审核、发布 | 医疗引擎运营员 |
| 平台管理 | 机构与人员、合规安全、系统运维 | 平台管理员、审计员 |

- 客户可分配职责固定为平台管理员、医疗引擎运营员、临床使用者、审计员。
- 内置超级管理员不可手工分配，并通过同一权限链获得全部能力。
- `MenuPermissionCatalog`、前端 `routes.ts` 和
  [功能目录](audit/product-function-catalog.md) 共同构成入口权威。
- 任何菜单和运行端点都必须被至少一个可分配职责覆盖。
- 前端只校验菜单和权限，不叠加角色硬编码。

### §2.1 入口承载规则

1. 左侧主导航只承载高频、稳定、可由客户任务解释的一级与二级入口。
2. 消息通知进入页头，个人通知偏好进入个人菜单，不重复占用侧栏。
3. 规则试运行、评估结果、发布步骤、验收自检等同一任务的子能力并入主页面，不保留双入口。
4. 来源与血缘、知识关系、模型能力、国产化核验和诊断工具与普通功能一样归入所属空间；低频证据可在页内“证据详情”按权限渐进展示。
5. 只服务 HIS、EMR、LIS、PACS、FHIR 或 Webhook 调用的能力接口化，不进入客户菜单。
6. 新页面必须归入现有产品空间，或明确为页头、个人菜单、页内步骤、嵌入终端或接口能力，并同步目录、路由和职责矩阵。

## §3 最小生命周期（禁自创强制门槛）

| 对象 | 最小生命周期 | 约束 |
|---|---|---|
| 资产稳定身份 | 有效 → 已退役 | 退役表示不再产生新版本；不得删除已被历史机构生效版本引用的身份 |
| 资产内容版本 | 草稿 → 已发布 → 已撤回 | 已发布版本不可改写；撤回用于阻止危险或错误版本进入新的机构生效版本，历史证据仍可重放 |
| 机构生效版本 | 准备中 → 当前生效 → 已替代 | 同一机构同时只有一个当前生效版本；回滚通过重新启用已验证版本或创建新版本完成 |
| 任务与告警 | 待处理 → 处理中 → 已完成；必要时可升级或关闭 | 只表达真实处理进度，不复用资产发布状态 |

## §4 统一最小发布流

```
创建/导入/生成草稿
→ 自动校验与测试
→ 依赖闭包和影响分析
→ 当前授权责任人确认发布
→ 纳入机构生效版本并留证/可回滚
```

知识、术语、规则、路径、评价、随访、值集、公式和安全等可发布资产复用这一流程。不存在强制
第二审核人、委员会、双签或默认灰度；确有风险控制价值时可以选择限定组织范围启用，但它是
机构生效版本的选择范围，不增加一套资产状态。账号偏好、连接参数和即时诊断操作只保留必要
校验、授权、审计与结果反馈，不套发布流。

## §6 临床医疗安全红线（视角：临床医疗安全）

- **辅助诊疗是上位能力**：辅助诊疗（CDSS）统筹诊断支持、检查检验建议、用药安全、治疗与处置建议、患者路径、风险预警等临床决策支持；推荐诊断与鉴别诊断是其中并列且可组合的诊断子能力，不是与辅助诊疗并列的“三层”，也不是必须依次执行的三阶段流程。
- **医师确认才进病历**：AI/CDSS 不自动开医嘱、上报、支付、签署、输血、手术、设备控制、病历归档。
- **AI 内容明显标识**："AI 候选 / AI 生成 / AI 建议"。
- **高风险强制技术门 + 逐条责任确认**：DDI、危急值、剂量上限、抗菌限制、特殊人群禁忌不得批量确认，必须展示来源、影响和回滚路径。
- **高危近似映射**（钾/钠、肌钙蛋白 T/I、左/右、剂量量级）强制 HIGH + 禁批量 + 禁自动确认。
- **旧版隔离**：新版生效后旧版退出新临床判断，仅历史重放。
- **临床知情同意**：涉及患者的高风险决策与 AI 辅助须可见同意/责任边界；页面文案不得暗示系统自动诊断/治疗。
- **静默试运行**通过后才允许打扰医生；嵌入提醒按打扰等级（信息/弱打断/红线强打断）。

## §7 知识与数据治理不变量（视角：知识与数据治理）

- **唯一权威知识**：同一适用域（knowledge_identity + organization_scope + applicable_population + effective_time）同时只有一个 `ACTIVE_AUTHORITATIVE` 版本；待审新版只审不执行；新版激活时原子失效旧版。
- **字典语义映射**：基于医学语义（同义词典 + 编码交叉表 + 模型嵌入），**禁字符 LCS**；高危近似负样本判别器强制 HIGH。
- **来源可追溯**：来源类型/标题/版本/引用位置/hash 100% 可回溯；证据分级 A 法规 / B 国家指南 / C 共识文献 / D 院内 / E 反馈（GRADE 兼容）。
- **关系库权威**：业务事实唯一权威源为院内关系数据库；图数据库（Neo4j）、Dify、模型、缓存只能是**投影或执行器**，必须可重建。
- **AI 工厂只产候选不产事实**：候选须经安全门禁 + 人工审核才能成为知识。
- **平台源知识不可污染**：平台主租户 `t-1` 是全局医疗知识和平台标准版本唯一主源，禁止再创建第二个技术平台租户；客户默认引用平台发布版本，本地定制只在本机构形成同源覆盖或新增资产，禁止反写平台主源。
- **机构生效版本只组合不复制**：机构生效版本只锁定精确资产版本和适用范围，不复制资产维护逻辑；同源修改按稳定资产身份解析机构覆盖，机构新增资产只归本机构。离线交付文件只传输平台标准版本或机构生效版本的完整快照，不成为医疗资产或动态运行指针。

## §8 安全合规与监管基线（视角：安全合规与监管）

- 等保 2.0 三级；国密 SM2/SM3/SM4；个保法（PIPL）；数据出境合规评估与备案。
- 敏感字段脱敏 + 字段级加密 + 审计；最小数据外调（字段允许范围 + 当前授权操作者确认用途与范围）。
- **审计链**全留证：来源 / 生成 / 审核 / 发布 / 运行 / 反馈 / 整改 / 回滚。
- 互联互通测评与电子病历评级支撑；**伦理与（数据）知情同意**（科研/RWD 须伦理授权 + 脱敏队列）。

## §9 集团化与多租户治理（视角：集团化与多租户）

- **边界与组织分离**：平台管理多个客户租户；租户是数据隔离和组织根边界。租户内组织树为集团 → 医院 → 院区 → 社区服务点 → 科室；专病和专业领域是资产适用范围与触发分类，不进入组织树。
- **平台主租户唯一**：`t-1` 永远且唯一为平台主租户和平台资产归属；`SYSTEM` 仅为系统配置与角色目录命名空间，不是可登录业务租户；客户租户由平台主租户开通和分发。
- **客户覆盖可定制**：客户 / 集团租户默认使用平台标准版本；本地修改同一稳定资产身份时生成客户覆盖版本，客户新增资产只归本机构。两者只有被选入机构生效版本后才参与临床运行，不得作为其它客户或平台主源的上游来源。
- **租户隔离**：跨租户数据不串；组织与数据范围必须随请求共同校验。
- **多维治理切片**：组织层级 / 临床对象 / 服务能力 / 生命周期 / 外部接入 / 风险证据；默认视图最多 3 维，更多进入证据详情。
- 医院可以按组织、场景、规则、路径、知识或任意选择集分批启用；依赖闭包不完整时禁止激活。

## §10 集成与互操作边界（视角：集成与互操作）

- 外部系统（HIS/EMR/LIS/PACS/手麻/输血/护理/医保/公卫/区域平台/外部服务商）**只经统一对接链路**：适配器 + 标准患者资源 + 临床事件 + 当前机构生效版本 + 嵌入 + 回调 + 审计证据。
- FHIR / CDS Hooks 风格门面；字段映射 / 健康检查 / 重试 / 死信 / 回放。
- 临床调用方不得传入离线交付文件、领域或资产版本；服务端按医院解析并锁定当前机构生效版本。
- **不绕引擎**直写医疗结论、医嘱、病历、法定上报、支付或设备控制。
- 同步超时不阻断医生主流程；断连诚实标 `NOT_CONNECTED`，不伪造连接。

## §11 AI / 模型治理与可降级（视角：AI / 模型治理）

- **B0 先于模型**（铁律 #4）：每个含 AI 增强的能力先交付"无模型确定性 + 人工"路径并验收，再叠加模型。
- 所有 AI 能力统一经**模型能力网关**：能力代码 / 路由 / 脱敏 / 结构化输出 / 审计 / B0 降级；**模型只产候选不产事实**。
- 提示词、工具、模型版本治理：可重放 / 可回滚 / 可导出 / 可审计（数据策略、模型模式、来源、版本、输出 hash、审核动作、降级情况）。
- 幻觉拦截与引用真实性；不把未核验内容标为"最新"。
- **降级诚实**：模型 / Dify / 图投影 / 外部系统 全部关闭时，主链路仍真实通过验收（返回 `B0`/`NOT_CONNECTED`/`NOT_SYNCED`/`MODEL_DISABLED`，绝不伪造）。Dify 仅可选运行器；图数据库仅投影。

## §12 运维 / SRE / 国产化交付（视角：运维 / SRE / 国产化）

- **内外网双形态**：内网（医院本地机房，国产化栈，业务权威源在院内关系库，不出网）/ 外网（SaaS，MySQL/PostgreSQL + Dify Cloud/OpenAI Compatible，数据出境合规评估）。任何功能都要回答"内网怎么用？外网怎么用？"
- **国产化栈**：麒麟 / 统信 / openEuler · 达梦 / 人大金仓 · KAE-JDK 21 / BiSheng JDK 21 · Ollama 本地大模型；国密算法 smoke。
- **5 方言迁移**：h2 / postgres / oracle / dm / kingbase 一致性 + 中文注释 + 索引约束。
- 监控 + 健康检查；备份恢复 RPO-RTO 与独立恢复演练。应用只读呈现备份就绪状态和演练证据，不直接执行数据库备份或恢复；内网离线运行依赖本地包、本地执行器和院内权威数据，不设置未经商业模型定义的许可闸门；SLA ≥ 99.9%；灾备。
- **降级链端到端**：模型 / Dify / 图 / 外部 四类逐项关闭后主链路可运行。
