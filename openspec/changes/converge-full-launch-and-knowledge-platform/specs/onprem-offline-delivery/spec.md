## ADDED Requirements

### Requirement: 不可变且可验证的院内软件包

发布流水线 SHALL 为一个已通过 clean 回归的完整 40 位提交哈希生成不可变院内软件包。软件包 MUST 包含后端 JAR、前端 `dist`、JRE 21、唯一数据库 V1、systemd 与 Nginx 模板、`preflight`、`install`、`upgrade`、`rollback`、`status`、备份恢复与验收入口、manifest、逐文件 SHA-256、SBOM、供应链证明和可选的已批准离线模型；完整软件包及 manifest MUST 使用受信任发布根签名，且发布流程不得重建或替换已经通过测试的二进制制品。

#### Scenario: 验证完整签名软件包

- **WHEN** 安装器接收院内软件包
- **THEN** 安装器 MUST 在解包或执行前校验签名信任链、manifest、提交哈希和每个文件的 SHA-256，并在任一校验失败时拒绝安装且不修改目标主机

#### Scenario: 发布制品与已验证提交不一致

- **WHEN** 软件包内任一制品无法追溯到通过 clean 回归的同一提交，或发布阶段重新构建了未验证二进制
- **THEN** 发布流水线 MUST 失败并禁止签名、上传或声明该包可交付

### Requirement: 空白 openEuler 24.03 LTS x86_64 与 PostgreSQL 16 幂等安装

首发正式安装合同 SHALL 面向空白 openEuler 24.03 LTS x86_64 主机、本机 PostgreSQL 16、Nginx、systemd、Java 21、静态前端、回环后端和受管本地资料盘。离线安装器 MUST 在无公网依赖条件下完成或验证运行依赖、初始化空数据库、只执行唯一 V1、安装服务、应用 site overlay、启动服务并执行真实 readiness；`preflight`、`install`、`upgrade`、`rollback` 和 `status` MUST 可重复运行且保持幂等。

#### Scenario: 空白主机首次离线安装

- **WHEN** 运维人员在受支持的空白 openEuler 24.03 LTS x86_64 主机上提供签名软件包、合法 site overlay 和独立凭据
- **THEN** 安装器 MUST 建立本机 PostgreSQL 16 与运行目录，应用唯一 V1，安装并启动 Nginx 和 MedKernel，并在严格 TLS readiness、数据库版本和制品摘要均通过后才报告成功

#### Scenario: 重复执行相同安装

- **WHEN** 运维人员以相同软件包和相同 site overlay 再次执行安装
- **THEN** 安装器 MUST 检测已满足状态，不得重复创建业务事实、重复迁移或改变当前生效配置，并返回可审计的幂等结果

#### Scenario: 安装事务中途失败

- **WHEN** 制品切换、数据库迁移、服务启动或 readiness 任一步骤失败
- **THEN** 安装器 MUST 停止后续步骤并恢复可恢复的安装前程序、配置和服务状态；若数据库已发生不可逆前向迁移，则 MUST 给出明确修复或备份恢复路径，不得把旧程序自动接到不兼容的新数据库

### Requirement: 无凭据的站点 overlay

site overlay SHALL 只描述主机名与外部地址、受信 CA 公共证书或坐标、数据库地址和库名、运行与资料目录、机构身份、集成端点、功能开关及非敏感网络参数。overlay MUST 不包含数据库密码、JWT 密钥、字段加密密钥、bootstrap 令牌、集成签名密钥、模型凭据、SSH 私钥或 TLS 私钥；所有凭据 MUST 通过独立受控通道在目标主机注入，并保存到最小权限的安全配置或凭据设施。

#### Scenario: 安装前校验 site overlay

- **WHEN** 安装器加载 site overlay
- **THEN** 安装器 MUST 进行 schema、路径、主机和敏感值扫描，在发现凭据、私钥、模板占位符或不安全文件权限时拒绝继续且不得在日志中输出敏感值

#### Scenario: 复制到另一医院

- **WHEN** 相同签名软件包部署到另一医院实例
- **THEN** 交付方 MUST 只更换该医院的 site overlay 并通过独立通道配置凭据，不得修改、重新打包或重新签名通用软件包

### Requirement: 严格 TLS 与 SAN 验证

正式院内入口 SHALL 使用 HTTPS，证书链 MUST 由系统信任库或 site overlay 指定的医院 CA 验证，叶子证书 MUST 在有效期内且 SAN 必须覆盖外部 URL 的 DNS 名称或 IP。安装、状态、升级和验收入口 MUST 执行严格 TLS 请求，不得使用跳过证书校验的参数或仅凭 HTTP 回环健康检查宣称外部入口可用。

#### Scenario: TLS 证书与外部地址匹配

- **WHEN** 安装器或验收器检查外部 HTTPS 地址
- **THEN** 系统 MUST 校验证书链、有效期、SAN 主机匹配和严格 readiness，并仅在全部通过时报告 TLS 就绪

#### Scenario: SAN 缺失或不匹配

- **WHEN** 证书缺少 SAN、SAN 不包含目标 DNS 名称或 IP、证书过期或信任链失败
- **THEN** 安装、升级或验收 MUST 失败，且不得通过关闭校验、自签忽略或改用明文 HTTP 绕过

### Requirement: 受管 file 资料盘

首发交付 SHALL 使用 site overlay 配置的独立 `file://` 资料根保存原文、原包、PDF、图片、OCR 和解析中间产物，推荐挂载到 `/zoesoft/medkernel-data` 或等价受管资料盘。资料根 MUST 位于应用发布目录之外，由 MedKernel 运行用户最小权限访问；写入和取回 MUST 防止路径越界并重算 SHA-256，与关系库资料账本一致后才返回内容。未配置、未挂载、不可写或摘要不一致时 MUST 诚实阻断相关能力。

#### Scenario: 安装时验证资料盘

- **WHEN** 安装器执行 preflight 或首次启动
- **THEN** 安装器 MUST 验证 `file://` scheme、规范化路径、挂载存在性、容量、权限、写入与读取摘要，并在不满足时拒绝将知识资料能力标记为就绪

#### Scenario: 资料盘运行中不可用

- **WHEN** 资料盘卸载、权限丢失、文件缺失或内容 SHA-256 与账本不一致
- **THEN** 系统 MUST 返回明确的资料库不可用或指纹不一致错误，不得改写关系库账本、切换到发布目录或返回伪造内容

### Requirement: 数据库、资料和配置的完整备份恢复

院内交付 SHALL 对 PostgreSQL 权威库、受管资料盘、运行配置、site overlay、制品 manifest、包注册与必要证书元数据形成同一备份清单和一致性边界。备份 MUST 具有 SHA-256、加密、访问控制、保留策略、失败告警和异机复制；包含凭据的运行配置 MUST 仅存在于加密备份中，签名私钥不得进入普通备份。系统 MUST 周期性在隔离的另一主机或等效异机环境完成数据库、资料和配置联合恢复并记录真实 RPO/RTO。

#### Scenario: 创建并异机复制完整备份

- **WHEN** 定时任务或上线前操作创建备份
- **THEN** 系统 MUST 生成绑定数据库快照、资料文件清单、配置版本、制品摘要和时间点的加密备份，校验摘要后复制到独立故障域，并在任一部分失败时将备份状态标记为失败

#### Scenario: 在另一主机恢复

- **WHEN** 运维人员使用备份在隔离的另一台受支持主机执行恢复演练
- **THEN** 恢复入口 MUST 先验证备份摘要和解密权限，再恢复数据库、资料及配置，重启服务并证明资料 SHA-256、当前机构生效版本、登录和 B0 运行一致

#### Scenario: 只有数据库或只有资料恢复成功

- **WHEN** 数据库、资料、配置中的任一组成部分缺失、版本不一致或校验失败
- **THEN** 恢复演练 MUST 整体判定失败并保留诊断证据，不得把部分恢复冒充灾备可用

### Requirement: B0 默认运行与可选离线模型

院内软件包 SHALL 在不安装、不配置或关闭模型时完整运行 B0 确定性与人工主链。离线模型只能作为可选附件交付，并 MUST 具有独立许可、权重 digest、模型定义、Provider 配置版本、安全门和医学基准评测证据；模型只能生成带 AI 标识且待责任人审核的候选，不得自动发布知识或执行诊断、医嘱、支付、签署、法定上报和设备控制。

#### Scenario: 不安装模型完成上线

- **WHEN** 医院选择不部署离线模型或模型 Provider 不可用
- **THEN** 系统 MUST 以 B0 完成登录、资产维护、审核发布、当前版本解析和确定性运行，并诚实显示 `MODEL_DISABLED` 或相应降级状态

#### Scenario: 启用可选离线模型

- **WHEN** 医院安装通过签名、digest、许可和医学基准验证的离线模型附件
- **THEN** 模型服务 MUST 仅监听回环地址，系统 MUST 记录真实权重与 Provider 版本，并将所有生成结果限制在有来源、有 AI 标识的候选状态

### Requirement: 最小端口和网络暴露

首发拓扑 SHALL 仅将 `443/tcp` 作为业务 HTTPS 入口公开；`22/tcp` MUST 仅允许受控运维来源；PostgreSQL `5432/tcp`、MedKernel `18080/tcp` 和可选 Ollama `11434/tcp` MUST 仅监听回环地址或不可从非授权网络访问。服务之间的内部连通和外部第三方未连接状态 MUST 分别验证，不得为了通过健康检查临时扩大暴露面。

#### Scenario: 安装后检查监听端口

- **WHEN** 安装或升级完成并执行网络验收
- **THEN** 验收器 MUST 证明外部仅可访问受信 HTTPS 入口、SSH 受来源限制且数据库、后端和模型端口不能从非授权网络访问

#### Scenario: 发现额外公开端口

- **WHEN** 验收器检测到 `5432`、`18080`、`11434` 或其它未批准服务端口对外监听
- **THEN** 系统 MUST 判定交付未通过并给出监听进程和修复信息，不得仅记录警告后继续宣称上线

### Requirement: 同一软件包复制到医院实例

134 平台环境和医院实例 SHALL 使用同一摘要、同一签名的软件包；医院复制不得重新编译、改写 manifest 或替换包内制品。医院可使用同一受信平台医疗资源包，通过不同 site overlay、机构身份和独立凭据完成安装、资源导入及本地激活，并在平台或 134 离线时继续使用最后一个已验证机构生效版本。

#### Scenario: 从 134 候选复制到医院

- **WHEN** 已在 134 验证的软件包和医疗资源包被复制到医院离线介质
- **THEN** 医院安装器 MUST 重新校验原签名和摘要，仅应用医院 site overlay 与独立凭据，并在不连接 134 的条件下完成安装、资源导入、B0 运行和回滚验证

#### Scenario: 医院现场修改通用包

- **WHEN** 医院交付介质中的通用软件包内容、manifest 或签名与 134 已验证候选不一致
- **THEN** 安装器 MUST 拒绝部署并要求重新取得原始签名包，不得现场补签后冒充同一候选

### Requirement: 真实 smoke 驱动的支持矩阵

正式支持矩阵初始 SHALL 只声明经过完整验证的 openEuler 24.03 LTS x86_64、本机 PostgreSQL 16 和受管本地 `file://` 资料盘组合。其它操作系统、CPU 架构、数据库、资料存储适配器、容器或模型拓扑即使具备代码、迁移方言或配置模板，也 MUST 在对应真实目标栈完成空机安装、升级、回滚、备份、异机恢复、严格 TLS、B0 和核心业务 smoke 后才可声明支持。

#### Scenario: 新技术栈通过真实 smoke

- **WHEN** 新的操作系统、架构、数据库或存储组合完成真实目标环境全套 smoke 且证据绑定具体版本和制品摘要
- **THEN** 系统 SHALL 将该精确组合加入支持矩阵，并记录限制、验证时间、驱动或依赖版本和回归入口

#### Scenario: 只有生成迁移或模板

- **WHEN** 某技术栈只有迁移生成、编译、单元测试、配置模板或模拟环境证据
- **THEN** 系统 MUST 将其标记为未验证或不支持，不得在交付说明、销售材料或上线结论中宣称正式支持

### Requirement: 脱敏且可重算的交付证据

安装、升级、备份、恢复和 smoke 证据 SHALL 绑定主机身份、run-id、候选提交、软件包摘要、数据库版本、资料清单摘要、执行时间和真实命令结果。证据汇聚 MUST 直接检查目标文件并重算摘要，不得只接收外部 JSON 文本作为成功证明；证据、日志和交付包 MUST 不包含凭据、私钥、接管码或患者明文。

#### Scenario: 生成院内交付验收证据

- **WHEN** 一次安装、升级或恢复流程结束
- **THEN** 系统 MUST 生成可独立重算的脱敏证据，并且仅在全部必需检查真实通过时记录 PASSED

#### Scenario: 证据包含敏感信息或不可重算

- **WHEN** 证据扫描发现凭据、私钥、患者明文，或关键摘要和目标文件无法重算
- **THEN** 系统 MUST 拒绝归档和发布该证据，将验收状态保持为失败或未就绪
