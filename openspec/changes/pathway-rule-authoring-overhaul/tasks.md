- [x] P0-2 `PathwayProgressor` 边 `guard` 改用 `ConditionEvaluator`，上下文来源切换为 canonical；既有扁平 `conditionJson` 适配为单叶子 Group（向后兼容，无需迁移）。

- [x] P0-3 新增 `CanonicalAllergyIntolerance` 资源 + 投影 + 字段目录纳入（解锁药物-过敏场景）。

## 交付顺序建议

1. **P0** 引擎基础（统一条件内核、过敏资源）—— 地基，解锁路径复用与药物-过敏场景。
2. **P1 + P3** 纯前端（递归条件树 + 路径易用性），直接解决「多层级」与「全手填」最痛点；P3 守卫边复用 P0 内核。
3. **P2** 字段目录（解锁字段选择器与单位/参考范围/值集元数据）。
4. **P6** 临床算子与函数库（兑现 L2 已承诺的临床判断能力，依赖 P0 内核 + P2 字段元数据）。
5. **P5** 字典对照与值集（解锁编码候选与上线覆盖门禁）。
6. **P7 → P8** 规则动作治理与知识治理生命周期。
7. **P9 → P10** 路径领域模型与变异/继承/结局。
8. **P4** 对外接入契约；**P11** 标准互操作映射。
9. **P12** 创作体验与资产复用：**自然语言预览(P12-1)、向导(P12-2)、即配即试(P12-3) 随 P1 同步交付**（直接提升可用性）；参数化/片段库/批量/资产库随 P2/P6 资产成形后强化。

> P1+P3 可在 P0-1/P0-2 完成后立即并行启动；P0-3（过敏资源）只阻塞药物-过敏类场景，不阻塞其余阶段。体验基线（P12-1/2/3）不是收尾项，应与 P1 一起做，避免「先难用再补救」。

每阶段结束更新 `_HANDOFF`，保证后续 AI 可按规格续作。低危规则/路径走简化流程，仅高危走会签/影子，治理分级避免拖慢上线。
