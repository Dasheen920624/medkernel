> 提案日期：2026-06-03
> 提案人：Claude
> 状态：提案设计中
> 关联：D2 试点准备域 `RULE-01` / `PATH-01`；核心 §7 规则 DSL；`docs/MEDKERNEL_PRODUCT_EXPERIENCE_RULES.md`
> 关联前端：`frontend/src/pages/tenant/PathwayTemplates.tsx`、`frontend/src/pages/tenant/RuleDefinitions.tsx`、`frontend/src/shared/config/ruleLayeredEditor.ts`
> 关联后端：`com.medkernel.engine.rule.RuleDslEvaluator`、`com.medkernel.engine.pathway.*`、`com.medkernel.engine.context.canonical.*`

## 1. 背景与动机

试点客户在「路径配置」和「规则库」两个核心创作入口反复创建失败、无法投入使用。实测暴露的系统性问题：

### 1.1 规则引擎（规则库）

- **条件树只有一层**：前端数据模型 `RuleConditionTree = { logic, conditions[] }` 是扁平结构（`ruleLayeredEditor.ts` 行 37-42），只能产出 `when:{all|any:[叶子...]}`，**无法表达 `A 且 (B 或 C)` 这类多层级临床判断**。而后端 `RuleDslEvaluator.evaluateConditionNode`（行 65-99）**早已支持任意深度递归 `all`/`any`**——能力被前端白白浪费。
- **上下文没有字典/数据源**：条件字段 `fact` 是裸文本 `context.<字段路径>`，要求临床配置人员手敲 `observations.0.value`，无字段目录、无数据类型推断、无枚举值候选，极易写错且无法校验。
- **同步即跳专家模式**：`syncTreeToDsl` 强制切到 L3（行 350-354），用户被反复甩进不该进入的专家视图，流程不可控。

### 1.2 路径引擎（路径配置）

- **节点编码与名称全要手填**：L2 节点画布每个字段都是裸 `<Input>`（`PathwayTemplates.tsx` 行 1027-1106），节点编码、边编码、源/目标节点编码全靠手敲。
- **边靠手敲编码连接**：`fromNodeCode`/`toNodeCode` 是文本框而非「从已建节点选择」（行 1154-1172），敲错即断链，拓扑校验失败。
- **创建静默失败**：起点必须等于某节点编码、设了时窗必须填时钟指标编码（行 571-588），但无字段级即时提示，手填不一致就报「创建路径模板失败」而不指明原因。
- **含义不清晰**：「时钟指标编码」「临床知识与指南基础」「条件 DSL JSON」等无说明、无示例、无候选。

### 1.3 共性

两个引擎都缺少「简单配置即可表达复杂逻辑」的渐进式创作体验，也缺少把院内字典与系统标准字典对照打通、对第三方开放数据接入规范的能力。

## 2. 改造目标

> 目标对标国际医学信息学标准（CDS Hooks、HL7 FHIR/CQL、Arden Syntax、GLIF/PROforma/PlanDefinition、UCUM、FHIR ValueSet），用于约束 DSL 语义与对外契约，不替换既有技术栈。详见 `design.md`。

### 2.1 体验与可视化
1. **规则：可视化嵌套条件树**——任意深度「条件组（全部满足/任一满足/取反）+ 叶子条件」嵌套，前端无损双向映射后端 `when` DSL，复杂临床逻辑无需写 JSON。
2. **路径：图形化拓扑创作**——节点编码自动生成可改、边下拉选已有节点连接、起点下拉、时窗/指标级即时校验，杜绝手敲断链与静默失败。
3. **渐进式专家模式**——普通配置只暴露可视化层；L3 DSL 仅显式进入专家模式时出现，同步不强制跳转，流程可预期。

### 2.2 规则引擎医疗级能力（兑现 L2 编辑器已承诺的临床算子）
4. **临床算子与受控函数库**——区间/参考范围比较、单位感知换算（UCUM 子集）、时间窗连续/趋势/计数/聚合、受控临床公式（eGFR/CrCl/BSA/BMI 等），均可在 L2 结构化配置。
5. **缺失/陈旧数据三值逻辑**——TRUE/FALSE/UNKNOWN 求值，按风险声明 fail-open / fail-safe，证据明示缺失，不以默认值伪造命中。
6. **分级动作与卡片式输出**——对齐 CDS Hooks Card（indicator/source/suggestions/overrideReasons），动作分级（提示/提醒/强提醒/阻断/建议医嘱/自动留痕）。
7. **规则交互治理**——优先级、抑制、去重、冲突检测、告警疲劳管理、越权理由留痕。
8. **适用域与生效**——人群（纳入/排除）、组织、场景（住院/门诊/急诊/随访）、生效期与灰度。
9. **知识治理生命周期**——评审→临床委员会会签（高危多签）→影子/静默运行→灰度→全量→监测→退役；含历史回测与漂移监测。

### 2.3 路径引擎医疗级能力
10. **临床路径领域模型**——真实入径/出径人群、阶段/里程碑/天序、富节点类型（决策/并行 fork-join/等待计时/子路径/人工闸门/医嘱套餐）、守卫式分支。
11. **临床时钟与 SLA**——里程碑目标/最早/最晚时限与超时分级升级（门球时间、抗生素时限等）。
12. **变异管理与角色 RACI**——变异捕获/分类/原因/再入径；节点责任角色与工作清单。
13. **多级模板继承与结局指标**——STANDARD→…→SPECIALTY 继承与差异合并；绑定 LOS/再入院/并发症/成本等结局指标；多路径并发冲突协调。

### 2.4 共性基础设施
14. **上下文字段目录 + 术语值集服务**——从 canonical 派生字段目录；编码字段绑定 FHIR 风格 ValueSet（外延/内涵 + `$expand/$validate-code/$subsumes`）；前台可维护。
15. **院内字典 ↔ 标准字典对照 + 覆盖门禁**——复用 terminology 域，未对照关键项阻断上线。
16. **对外数据接入契约（版本化）**——基于字段目录与值集沉淀第三方接入契约文档，随 packageVersion 版本化。
17. **标准互操作映射**——规则↔CDS Hooks/CQL、路径↔PlanDefinition/GLIF 的加法式导出适配器。

### 2.5 引擎基础（代码审计补充，列为 P0 前置）
19. **统一条件求值内核**——抽取 `ConditionEvaluator`，规则 `when` 与路径边 `guard` 共用同一递归文法与 canonical 上下文（审计发现路径当前是单层 facts-map 条件，与规则分叉），既有扁平边向后兼容。
20. **补齐过敏资源**——canonical 模型当前无过敏/不耐受资源，药物-过敏核查无法表达；新增 `CanonicalAllergyIntolerance` 作为前置。
21. **复用 terminology 真实能力**——院内↔标准对照与高危语义匹配复用既有 `LocalTerm/StandardTerm/TermMapping/TermMappingPackage/SemanticTermMatcher/HighRiskTermDetector`，值集建于其上。

### 2.6 创作体验（简单·易用·易配·可批量·可复用）
22. **简单**——自然语言预览（条件树→可读中文句子）、原型向导、智能默认、渐进披露，会读会填就能用。
23. **易用**——即配即试（草稿+真实快照就地试运行+证据）、就地定位校验、搜索一切、克隆/另存为、版本差异、撤销重做。
24. **易配**——参数化规则（仅填阈值/值集/时限即成规则）、值集可视维护、字段目录浏览、适用域影响预览。
25. **可批量**——批量导入导出、模板×参数表批量生成、批量发布/分发到多组织（复用 `pkg` 离线导入与 `SyncTarget`），高危逐条确认。
26. **可复用**——条件片段库（按引用复用，变更走影响分析）、统一资产库（编目/标签/收藏）、集团共享库订阅、值集/医嘱套餐/子路径/动作卡片构件复用。

### 2.7 非功能、安全与运维
28. **医疗级硬化**——CDS 时延预算与诚实降级、创作职责分离（作者≠会签≠发布）、真实脱敏测试数据、环与边界检测、引用与包版本一致性、领域事件集成（待办/通知/质控驾驶舱）、能力开关灰度上线与回滚（详见附录 H）。

### 2.8 集成与落地
29. **医院系统对接与场景落地**——经适配器中心接入 HIS/EMR/LIS（诚实健康状态）、临床事件触发求值（对应 CDS Hooks）、投影期字典归一、Outbox 可靠分发到既有页面与回写；以专病包封装路径/规则/值集跨院分发，并给出专病诊疗（CKD）与实时临床决策（开医嘱）端到端落地路径（详见附录 I）。

### 2.9 工程
30. **一次性彻底改造、可持续推进**——按 OpenSpec 分阶段（P0→P11），每阶段独立可交付、可验证、可回退；附配套设计附录（DSL 文法/DDL+API/场景矩阵/枚举术语），保证后续 AI 照此续作。

## 3. 影响范围

### 3.1 前端

- `frontend/src/shared/config/ruleLayeredEditor.ts`：扁平模型重写为递归节点模型，序列化/反序列化改递归。
- `frontend/src/pages/tenant/RuleDefinitions.tsx`：L2 条件树改为递归可视化树；字段选择器接入；同步与专家模式解耦。
- `frontend/src/pages/tenant/PathwayTemplates.tsx`：L2 节点画布自动编码、边下拉选节点、起点下拉、字段级校验、文案与帮助。
- 新增字段选择器、字段目录维护页、字典对照维护组件（位置见 design）。
- 配套更新 `*.test.ts(x)`。

### 3.2 后端

- **规则评估器加法式扩展**（不重写内核）：在 `RuleDslEvaluator` 新增临床算子分派（区间/参考范围/危急值/时序/缺失）、`evaluateExpression`（聚合/量词/时间窗）、`ClinicalFunctionRegistry`（受控公式白名单）、UCUM 子集单位服务、三值逻辑与缺失数据策略。
- **动作与治理**：分级动作/卡片输出模型、规则优先级/抑制/去重/冲突、越权理由留痕、适用域判定、影子/静默运行与回测、知识治理状态机扩展。
- **字段目录与术语值集**：`GET /context/field-catalog` 只读 + 维护接口；FHIR 风格 ValueSet（外延/内涵）+ `$expand/$validate-code/$subsumes`；以 `engine.context.canonical.*` 为权威派生，配套幂等迁移。
- **字典对照**：院内↔标准映射查询与维护（复用 `terminology` 域，不另起并行事实源）+ 对照覆盖发布门禁。
- **路径领域模型扩展**：入径/出径条件、阶段/里程碑、富节点类型、临床时钟 SLA、守卫边、变异、角色、继承差异、结局指标绑定、多路径冲突。
- **标准互操作**：规则↔CDS Hooks/CQL、路径↔PlanDefinition/GLIF 的加法式映射器。
- 规则/路径校验接口补充字段路径与单位/值集合法性校验（基于字段目录）。

### 3.3 文档与 API

- 新增第三方数据接入 API 规范文档与字段契约。
- 更新 `docs/backlog.md` 中 `RULE-01`/`PATH-01` 承接说明。

### 3.4 后端改动定位（重要修正）

- **嵌套条件树**：后端 `RuleDslEvaluator` 已递归支持，**零改动**，仅前端补齐产出能力。
- **临床算子与函数库**：当前评估器只有 10 个时间点算子，**没有**区间/参考范围/单位/时序/公式能力。L2 编辑器已对用户承诺这些临床算子，因此必须**加法式、受控**扩展评估器，可灰度、可回退，不重写内核、不替换技术栈。
- **其余增量**（字段目录/值集/对照/变异/适用域/动作模型/路径领域）均为独立增量表与服务，配套幂等迁移。

### 3.5 明确不做

- 不重写或替换规则评估内核与既有发布/回滚链路（只做加法式扩展）。
- 不替换既有技术栈（Spring Boot / React + Antd）。
- 不引入第三方规则引擎（Drools 等）或允许运行期任意表达式/脚本注入（医疗安全红线）。
- 不在前端伪造字段目录、值集或字典数据；目录与对照必须来自后端真实派生与维护记录。
- 不以默认值/随机值伪造规则命中或路径推进；缺失数据按三值逻辑诚实处理。
- 不重新设计推荐引擎（`engine.recommendation`）：它已存在并由 `RecommendationEngineAdapter` 消费同一临床事件与归一上下文；本变更仅保证规则/路径产出可与其协同，不改其内核。
- LLM 仅用于创作期建议（复用 `ModelGateway`），绝不进入运行期求值、不自动发布（见附录 G6b）。

## 4. 提案结论

后端递归能力与 canonical 模型是坚实底座。本次改造的本质是：在不重写内核的前提下，**(1)** 把已有递归能力通过世界级渐进式创作体验暴露出来；**(2)** 受控扩展临床算子与函数库，兑现产品对临床判断能力的承诺；**(3)** 补齐字段目录、术语值集、字典对照、变异管理、知识治理这一整套医疗级基础设施。改造完成后，临床配置人员用简单配置即可表达复杂、可解释、可审计的临床逻辑，第三方可按版本化契约接入数据，规则与路径引擎真正达到可投入生产、医学可辩护的水平。
