# 附录 D — 资产依赖与引用完整性 / 一致性快照

> 目标：规则/路径/字典/字段相互引用，平台与覆盖独立演进时不得产生"悬空引用"或"撕裂读"，床旁拿到的永远是一套自洽的有效资产。

## D1 资产依赖图
资产间存在真实引用：
- 规则 → 引用字段目录字段、标准字典编码、其它规则（子规则）。
- 路径节点 → 引用规则、医嘱集/字典、字段。
- 知识包 → 引用一组资产版本。
- 评估/随访 → 引用规则与字段。

系统 SHALL 维护 **资产依赖图**（`asset_identity` → 依赖 `asset_identity` 集合 + 版本兼容范围），随版本登记建立/更新。

## D2 引用完整性约束
- **发布前校验**：平台或租户发布某资产版本时，校验其依赖在目标作用域内"可解析且兼容"，否则阻断并指明缺失项。
- **DISABLE 防悬空**：对被其它**在用**资产依赖的资产执行 DISABLE，须先处理依赖（拒绝或级联提示），不得产生悬空引用。
- **删除即弃用**：资产不物理删除，只走弃用/退役（附录 L），保留历史引用可重放。

## D3 协同解析（co-resolution）
解析某资产时，其依赖 SHALL 在**同一解析上下文**内一并解析：
- 规则解析时，连带解析它引用的字典/字段的有效版本，确保"平台规则新版 + 院内字典覆盖"组合自洽。
- 依赖解析遵循同一组织闭包 × 维度 × 权威层规则（附录 O）。

## D4 一致性快照（resolution epoch）
- 单次临床决策/单次有效包合成在一个 **resolution epoch** 内完成：epoch = 平台包激活版本游标 + 租户覆盖版本游标。
- epoch 内所有资产与其依赖取同一时点视图，杜绝"规则 v2 + 字典 v1"的撕裂读。
- 缓存与 `VersionReplayBinding` 均以 epoch 为锚，事后可整体重放该 epoch 的有效集（呼应附录 S5）。

## D5 版本兼容与契约
- 资产对其依赖声明**兼容范围**（如"字段 schema ≥ v2"）；依赖升级超出范围 → 触发影响信号 + 阻断不兼容自动下发（呼应升级通道 §8.5）。
- 字段目录/字典作为被广泛依赖的"契约层"，其变更走更严格评审（REVIEW），破坏式变更须新身份或主版本跃迁。

## D6 落地对接
- 依赖图存储：`asset_dependency`（asset_identity, depends_on_identity, min/max version, kind）；随各域适配器登记。
- 校验下沉各域 `DependencyValidator`；解析层 `InheritanceResolver` 暴露 `resolveWithDependencies(...)`。
- 复用 `VersionContentHash` 做 epoch 锚 + `VersionReplayBinding` 固化。
