# 附录 N — NFR、迁移与运维（平稳）

> 目标：升级不惊扰、迁移不停机、床旁不卡顿、故障可恢复、漂移可观测。

## N1 性能 NFR 与解析 SLA
- **床旁解析 P99 ≤ 50ms**（命中缓存 ≤ 5ms）；批量有效包解析 P99 ≤ 200ms。
- **无 N+1**：一次取组织闭包（`org_closure` 已物化）+ 一次批量取覆盖（按 `asset_identity IN (...)` + org 闭包）+ 一次批量取版本。
- **缓存**：键 `(tenantId, orgPath, packageActiveVersion, assetType)`；值=解析后有效集。默认应用内缓存（D4），TTL + 事件失效。
- **精确失效**：平台发布 / 覆盖增删改 / 红线变更 / 钉点切换 发布失效事件，按 `asset_identity`/org 子树定向失效，避免全量抖动。
- **可选物化**：超大租户可对热点机构物化"有效包视图"，以读放大换延迟（二期，按需）。

## N2 一致性快照（呼应依赖完整性附录）
- 解析以 **resolution epoch**（= 平台包激活版本 + 租户覆盖版本游标）为基准，单次决策内对所有资产用同一 epoch，杜绝"规则新版 + 字典旧版"的撕裂读。
- 缓存条目带 epoch；epoch 推进即整体换新，读旧 epoch 直至完成。

## N3 零停机迁移（双轨 + 桥接）
分阶段（tasks P0–P6），每阶段可独立回退：
1. **影子写**：各域 publish 同时写旧版本表 + 底座 `AssetVersion`（双写），读仍走旧路径。
2. **影子读校验**：后台对比"旧路径结果"vs"底座解析结果"，差异告警，零业务影响。
3. **灰度切读**：按租户/机构灰度把读切到底座解析（附录"模拟/灰度"）。
4. **下线旧路径**：稳定后停旧表语义（D5 二期物理合并）。
- 全程 **诚实降级桥**：平台基线缺失→回退本租户遗留版本并标 `sourceTier=LEGACY`，绝不阻断业务。

## N4 存量回填 Playbook（tenant 平铺 → 平台/覆盖）
现有 tenant 平铺的规则/字典/路径/字段目录需分类落位：
1. **抽取候选平台基线**：跨租户内容相同/高度相似者 → 提升为平台 `AssetVersion`（人工复核 + content_hash 聚类辅助）。
2. **建立身份映射**：旧记录 → `asset_identity`（附录 J 身份治理），保证改名/迁移稳定。
3. **租户差异转覆盖**：与平台基线不同的租户内容 → 生成 REPLACE 覆盖；租户独有 → ADD。
4. **校验**：回填后对每租户跑"影子读校验"确保解析结果 == 迁移前可见内容（零回归）。
5. **可回滚**：回填脚本幂等、保留快照，可整体回退。

## N5 并发与事务
- 平台发布与租户覆盖并发：以版本游标 + 乐观锁；激活走 `VersionActivationTransaction` 原子切换。
- 覆盖写入校验"基线版本指针"是否仍最新；上游已变更则提示 rebase（§11），不静默覆盖。

## N6 离线/断网与对账（SyncTarget）
- 断网机构持"解析后有效包快照"本地执行；重连后对账：拉取最新有效包，diff + 受控合并；本地若有离线产生的覆盖，走冲突解决（以平台/在线为权威，本地降级为待评审覆盖）。
- 下发与对账幂等（复用现有 idempotency 机制），失败可重试不重复。

## N7 可观测与漂移看板
平台/租户两套面板：
- **采纳率**：各平台版本被多少机构使用 / 落后 N 个版本的机构清单。
- **覆盖漂移**：每机构相对平台的 REPLACE/DISABLE/ADD 数量与趋势；"高漂移"机构预警。
- **解析健康**：解析延迟 P50/P99、缓存命中率、失效风暴、LEGACY 回退占比。
- **安全治理**：LOCKED 拦截次数、放宽尝试、待评审覆盖积压、过期/待复审知识数（附录 L 新鲜度）。
- **失败模式**：NOT_FOUND 率、悬空引用告警、对账冲突数。

## N8 容量与多租户规模
- 设计目标：≥ 数千租户 × 多层组织（附录 O 可变层级）× 数万资产，解析为闭包内增量计算，复杂度与"本机构覆盖数"相关而非"全平台资产数"，天然横向可扩展。
- 缓存与失效按 org 子树分片，避免跨租户互相影响。
